## 2. Golden Rules (read first)

> **Product principle:** the app is made for **ease of use** by non-experts and is **optimised as far as possible while preserving every feature**. Prefer sensible defaults and automatic behaviour over new dialogs, modes and settings; keep pro-only extras behind advanced options. Keep hot paths cheap (render, mouse-move, 3D build): no per-frame allocation, do work lazily. Never remove an existing feature to simplify — streamline or tuck it away instead.

1. **No dependencies, no build.** Do not introduce npm, bundlers, frameworks or TypeScript. The app must work by double-clicking `index.html`. The only exception is the optional `mcp/` tooling, which is also zero-dependency Node and must never be loaded by `app.js`.
2. **Keep all UI text bilingual (`tr` / `en`)** using `L('Türkçe', 'English')` (labels, toasts, prompts, modal text, catalog items). Code identifiers and comments may be English or Turkish — match the surrounding code.
3. **State is the single source of truth.** Mutate `P` (project) → call `commit()` → call `refresh()`/`render()`. Never read geometry back from the DOM.
4. **Always `commit()` after a completed user action** (not on every mousemove) so undo/redo and autosave work.
5. **Never hardcode plan colors** in SVG builders — use `pal()` (see §7). Exports must stay on white paper.
6. **Do not break the export pipeline:** `exportSvg()` sets `ui.exporting = true` and `view.z = 0.5` while calling builders; builders must be pure functions of `(object, live)`.
7. **Preserve existing comments/docstrings** unrelated to your change.
8. Run `node --check app.js` and the test suite (`node --test tests/*.test.js`, `node tests/browser-smoke.js`) before every commit, then verify visually what tests cannot judge (see §10).

## 3. Data Model

All persisted state lives in one object `P` (the *project*). It is JSON-serialisable and is exactly what gets saved to IndexedDB / exported as `.json`.

```jsonc
P = {
  "v": 2,                       // schema version
  "name": "Yeni Proje",
  "grid": 10,                   // grid step in cm (any number 1..10000)
  "gridType": "square",         // "square" | "triangle" | "dots" | "none"
  "wallT": 20,                  // default wall thickness (cm) for new walls
  "wallH": 270,                 // default wall height (cm) for new walls / floor pitch in 3D
  "bg": null | { "img": "<image id>", "x": 0, "y": 0, "w": 1200, "h": 800, "op": 0.5, "lock"?: true },   // image bytes in IndexedDB 'textures' (see *Storage*); old saves / links / JSON files carry "src": "<dataURL>" instead
  "layers": [ { "id": "0", "name": "Varsayılan", "color": "#64748b", "vis": true, "lock": false, "print": true, "z"?: 150 }, … ],   // drawing layers (issue #32); "0" = Default, cannot be deleted; z = layer height (cm, ±500)
  "activeLayer": "0",            // new objects are stamped with it (any object may carry "layer": id; absent = "0")
  "group"?: "Ahsen’s projects",   // optional project group (≤ 40 chars, cleanGroup in normalizeProject; absent = no group): gathers tabs and My Projects sections
  "qty"?: { "prices": { "fin:wood": 45, "op:door:90x210": 3500 } },   // optional unit prices per quantities line (#199)
  "site"?: { "lat": 41.01, "lon": 28.98, "tz"?: 3, "north"?: 15 },   // optional project location + true north (° clockwise from plan up) for the 3D sun (#205)
  "lw": { "wall"?: 3, "op"?: 2, "furn"?: 0.5, "room"?: 1.5, "anno"?: 0.75 },   // optional line-weight multipliers (LW_STEPS), absent = ×1
  "textures": [ { "id": "…", "name": "…", "w": 60, "h": 60 }, … ],   // custom texture metadata (issue #40); image data lives in IndexedDB
  "floors": [ Floor, ... ]

Floor = {
  "id": "…", "name": "Zemin Kat", "slabFloor": "none", "slabColor": null,   // 3D slab finish (same kinds as room floors)
  "wallH"?: 350, "glass"?: "clear|frosted", "noSlab"?: true,   // optional per-floor wall height (#59; absent = P.wallH), glass kind when slabFloor is "glass" (#57) and noSlab = no automatic floor slab

```
*(Any floor object above may carry `hidden?: true` (#174) to hide it from 2D, 3D, exports, picking and snapping until restored from the Hidden items panel.)*
`Floor.groups` = `[ { id, vars: [{ label, poses: {id: pose}, base?, draft? }], idx } ]` — adjustable layout records for grouped objects (see §8).

Key semantics:

- **Adjustable-angle (hinged) walls:** any wall may have `pivot` (`'a'` default or `'b'`) as its fixed point, `angles` (array of preset angles in degrees `0..360`), and `posIdx` (active position index). Clicking a hinged wall in 2D (`pointerup` without drag) or 3D (`Raycaster`) cycles `posIdx` (`1 → 2 → 3 → 1`) via `cycleWallPos(w)`. Dragging the `wrot` handle rotates the free end around `w[wallPivot(w)]` at constant length and updates `w.angles[w.posIdx]`.
- **Openings (`ops`)** are *parametric on a wall*: `d` = distance in cm from the wall's `a` end to the opening's **centre**. Moving/resizing/rotating a wall moves its openings automatically. Deleting a wall deletes its openings (`deleteIds`).
- `op.type` ∈ `door | double | slide | arch | window`. `side` (+1/−1) = which side the door swings to (local +Y = wall normal `(-uy, ux)`); `flip` mirrors the hinge / sliding direction. Clicking a door in 2D or 3D toggles `open` (`door`/`double` swing 90°, `slide` slides open).
- **Furniture** `k` ∈ `rect | round | stairs | bed | sofa` selects the 2D/3D shape. `rot` is degrees, clockwise on screen. "Back" of an item is local −Y (used by `magnet()`).
- **Rooms** are polygons. A room made by detection (`autoRoomAt`: the Auto Room tool, templates, **↻ Redetect**) carries `wb: 1` and **follows its walls** (#201): `commit()` → `followRooms()` compares the active floor's wall signature (`wallSigOf`, kept in `wallSig`, not in `P`) with the last one and re-detects every bound room (`roomFollows`: not hidden, no own `vars`, not in a group with layouts) from a point inside its old outline (`roomRedetect`). A leak / failure keeps the old corners and toasts one bilingual warning. `wallSigReset()` (restore / undo / redo, `loadProject`, `activateTab`) only moves the baseline. Manually drawn rooms have no `wb`; dragging a room corner / edge handle (`doHandle`) drops it; the room panel's **🔗 Follow its walls** (`roomwb`) toggles it (turning it on re-detects at once). Not built: live updates during the drag, slabs / zones following walls. Guard: smoke check "rooms that follow their walls".
- IDs are 7-char random strings from `uid()`; ids are unique across all kinds, so `find(id)` can search every array.
- Missing fields on old projects are defaulted in `loadProject()` (e.g. `gridType`, floor arrays). **When adding a field, add a default there** so old saves/JSON still load.

### Rendering pipeline
`render()` rebuilds SVG layer strings (`layerStrings(f, live=true)`) into fixed groups: `gBg, gGrid, gRooms, gWalls, gOps, gFurn, gDims, gTexts, gSketch, gSel, gPv` (z-order bottom → top). `gPv` (preview) is redrawn alone by `drawPreview()` on mouse-move. Hit-testing uses `data-id` (objects) and `data-h` (handles) attributes with `e.target.closest(...)`; invisible `stroke="transparent"` / `fill="transparent"` shapes provide generous hit areas.

**Once per frame.** Hot paths (pan, wheel zoom, `doMove` / `doHandle`, live panel `input`) call `scheduleRender()` instead of `render()`: one `requestAnimationFrame` draw per frame however many events arrive. `scheduleRender(false)` (pan) only runs `renderView()` = `applyView()` + `gridSvg()` — layers are in world coordinates, so the transform moves them (0.2 ms vs ~150 ms for a full render of a large plan). A synchronous `render()` cancels any pending frame, so `commit()` + `refresh()` on pointer-up always draws the final state. Only `gridSvg()` reads `view.x / view.y`; if a builder ever starts culling to the viewport, pan must use a full render.

**Zoom preview + unchanged layers.** Building the layer strings is cheap (~1 ms on a large IFC plan); the browser parsing and repainting them is not (~15 ms+, worse in normal 2D than CAD because of fills, patterns and detailed furniture). So: `zoomAt` and the touch pinch call `zoomPreview()`, which only does `scheduleRender(false)` (transform + grid, like pan) and one full render `ZOOM_SETTLE` (140 ms) after the last step, so strokes and labels are sharpened once instead of on every wheel notch. `render()` writes every group through `setLayerHtml(id, html)`, which skips the DOM when the markup is unchanged (a furniture drag no longer re-parses walls, rooms and dimensions every frame). Nothing else may write into `#defs` / `#gBg` … `#gSel` or edit their elements in place — the cache would go stale; write through `setLayerHtml` or re-render. Guard: the smoke check "2D speed: …".

When `live=false` (export, thumbnails) builders omit `data-id` and hit shapes.

## 7. Theming (Dark / Light)

- Chrome (panels, buttons) uses CSS variables in `style.css`: dark in `:root`, light in `[data-theme=light]`. `--stage-bg` / `--cv-bg` colour the stage, canvas, 3D container and thumbnails.
- Plan graphics use **`pal()`** in `app.js`, which returns a palette (`wall, stroke, gMin, gMaj, text, sub, halo, dim, glass, swing, roomOp, furnOp, wood, tile, carpet, marble, concrete, stone, …`).
  - `pal()` honours `ui.exporting`: when true it **always returns the light palette** so PNG/SVG/PDF are print-ready.
  - Door/window cut-outs are filled with `pal().bg` so they "erase" the wall; keep that in sync with `--cv-bg`.
- The theme button (`bTheme`) toggles `data-theme`, persists to `localStorage['fp_theme']`, calls `render()` and rebuilds 3D if open.
- `build3D()` reads `isLight()` for sky, ground, slab, wall colour and edge lines.

**Adding a new drawable?** Pull every colour from `pal()`, give text a `paint-order="stroke"` halo using `pal().halo`, and test in both themes.

## 8. Subsystem Notes

### Snapping (`snapPt`, `snapToGrid`, `magnet`)
- Order: wall-end / room-corner snap (14 px radius, only if `ui.snap` and no `Shift`) → angle snap when a `from` point exists and `ui.angle` → grid snap.
- Angle step: **15°** (square/dots/none), **30°** for `gridType==='triangle'`. Length rounds to `P.grid` except when `gridType==='none'`.
- `snapToGrid` is the **only** place that knows about grid geometry. Triangle lattice vertices: rows spaced `g·√3/2`, odd rows offset by `g/2`. Use it for any new placement/move feature instead of `rnd(v, P.grid)`.
- **Object snap tracking (issue #16):** after end-snap, `snapPt` aligns with reference points from `trackRefs()` (wall ends, room corners, in-progress `ui.polyPts`; excluding `ignore` and `from`). With `from` + angle lock it intersects the angle ray with each reference's vertical/horizontal line and locks the length (overriding grid rounding); otherwise x and y lock independently (both = the crossing of two references). Tolerance `10 / view.z`. The result carries `guides: [{from, axis}]`; `drawPreview()` draws them dashed (only while drawing or dragging a handle). `doHandle` sets `ui.cur` for `wa/wb`, `v<i>` and `da/db` so drags show guides too. `ignore` may hold wall ids **and** point objects (a dragged room vertex skips itself). Guard: `tests/snap-tracking.test.js`.
- **Midpoint / centre / underlay snap (issues #25, #26):** when no wall end or corner is within the 14 px radius, `snapPt` takes the nearest of `underlayPts()` (`hit: 'under'`), `snapMids(f, ignore)` (wall + dim midpoints, `'mid'`) and `snapCenters(f, ignore)` (room / slab / void centroids + group bbox centres, `'center'`). `ignore` keeps a dragged wall / dim / room vertex / group member from snapping to its own moving midpoint or centre (dim handles pass `new Set([o.a, o.b])`). `drawPreview()` draws the glyph with `snapGlyph()` (▲ / ⨁ / ◇ + a bilingual label) and, while a drawing or place tool is active, a faint ⨁ at the centre of the room under the cursor. Furniture locks to `nearCenter()` (18 px) in `updateGhost()` and in a single-item `doMove` instead of `magnet()`. Guard: `tests/snap-mid-underlay.test.js` + a smoke check.
- **Floor underlay (issue #26):** `underlayFloor()` = the floor picked in **Project ▸ Layers** (`underlay.floor`), else the floor below; `null` when `layersVis.underlay` is off, there is one floor, or the ground floor has nothing below. A floor picked as its own reference falls back to the floor below. `underlaySvg()` draws it into `#gBg` at `underlay.op` (10–50 %) with `pointer-events="none"`: wall joints + walls, slab outlines (dashed), voids, and stairs / columns (`isStructFurn`). Never exported. `underlayPts()` feeds both `snapPt` and `trackRefs`.
- `magnet(f)` snaps a furniture item to the nearest wall face and rotates it so its back (−Y) touches the wall.

### Grids (`defsSvg`, `gridSvg`)
- Patterns `g-minor/g-major`, `g-tri-*`, `g-dots-*` are rebuilt on every render (stroke widths depend on `view.z` to stay hairline).
- **Adaptive metric grid (issue #38).** The drawn interval comes from `gridScale(z)` = `{ minor, major, minorPx, majorPx }`: `minor` is `P.grid` while its spacing is ≥ `GRID_MINOR_PX` (6 px), else 0 (hidden — the old "hide the minor grid" rule, now explicit); `major` starts at the classic fixed interval (`P.grid ≥ 100 → 5×`, `≥ 25 → 4×`, else 1 m — rounded up to a multiple of `P.grid` when 1 m is not one) and climbs the `gridFactor()` ladder (×2 / ×5 / ×10 / ×20 …) only while it is closer than `GRID_MAJOR_PX` (46 px), so it is **always** drawn, always a multiple of `P.grid` (major lines sit on minor lines), and the grid looks exactly as before at normal zoom. For the default 10 cm step (and 25 cm) this walks 1 m → 2 m → 5 m → 10 m → 20 m → 50 m → 100 m → 500 m as you zoom out. `defsSvg()` sizes the tiles from `gridScale()` (falling back to `P.grid` when the minor grid is hidden); `gridSvg()` has no `view.z` gate any more. Pattern bodies come from `gridTile(kind, step, major)`; when a tile would be wider than `GRID_TILE_MAX` (512 px) on screen (e.g. a 4 m step: 20 m major tile = 8000 px zoomed in, which browsers rasterise as one huge bitmap), `gridSvg()` draws the few visible tiles directly (translated copies of the same body) instead of a pattern rect.
- **Zoom range.** `MIN_ZOOM = 0.002` / `MAX_ZOOM = 8` (≈ 2 km across a 1000 px canvas, ~5 km at 1400 px) are shared by `zoomAt()` and `fit()`, so a site plan can be framed with **0 / Fit**. `applyView()` prints the active interval in `#gridlbl` ("Izgara 1 m") and keeps `#zoomlbl` readable below 1 % (one decimal).
- **Snapping stays on `P.grid`.** `snapToGrid()`, `snapPt()` and the adaptive grid are deliberately independent: the drawn step is visual only, so pointing never jumps when the grid coarsens.
- `syncGridUI()` must be called whenever `P.grid` / `P.gridType` changes outside the footer controls (load, undo/redo) — it handles the "Özel…" custom-step input.

### Wall corners (`wallJoints`, issue #14)
Wall bodies end **butt** (flat) at their endpoints in 2D and 3D. `wallJoints(f)` groups coincident endpoints (≤ 1 cm), sorts the walls by outward angle and intersects neighbouring face lines to find each miter point; the convex hull of the butt corners plus the outward miter points is the filler polygon. Miters longer than 2.5 × max thickness are dropped (bevel). `jointsSvg()` fills it with `pal().wall` in 2D; `build3D()` extrudes it to the lowest solid wall height. T-junctions (an end on another wall's middle) need no filler — the through-wall covers the butt end. Guard: `tests/wall-joints.test.js` runs the real functions cut out of `app.js`.

### Numeric wall length (issue #36)
`applyWallLength(w, len, end = wallFree(w), conn = ui.connWalls)` moves the free end along the wall's own direction (a hinged wall keeps its pivot), drags coincident ends of other walls (< 1 cm) when `conn`, and keeps openings in place (`d` shifts when the `a` end moved) clamped to the new length — for the wall and for every connected wall it moved. Three entry points: a single selected wall + digits / `Enter` (`ui.lenTyped`, shown by `drawPreview`; `Backspace` edits the buffer instead of deleting); the canvas length label (`wallDimSvg` carries `data-wdim` except while exporting → `openWallDimInput()` puts a fixed `#wdimInput` over it); digits typed while dragging a `wa`/`wb` handle (`ui.drag.typed`; `doHandle` places the end exactly that far from the other end, toward the cursor). The panel `len` field uses the same routine on `change` only, so half-typed values never squeeze openings. Guard: `tests/wall-length.test.js` + a smoke check.

### Trim / split / corner (issue #15)
`trim` tool (`X`): `wallCuts(w)` lists where other wall centrelines cross `w` (cm from `a`, ends excluded); `trimPlan(w, click)` picks the nearest crossing on each side of the click and `trimWall()` removes that piece — an end overhang moves the end, a piece between two crossings splits the wall (`splitWallAt`). Openings on the kept part are re-based, those on the removed part are deleted via `deleteIds`. The hover preview paints the doomed piece red. Wall panel: **✂ Split at intersection** (`splitx`, one wall) and **⌐ Join corner** (`corner`, exactly two walls → `joinCorner()` moves each wall's nearer end to the line intersection, trimming or extending). Guard: `tests/wall-trim.test.js`.

### Free slabs & floor voids (issues #22, #23)
- `slab` (`K`) and `void` (`Y`) are polygon tools like `poly` (`POLY_TOOLS`): the first press starts a `prect` drag — dragging makes a rectangle, a plain click starts click-the-corners (Enter / first point / double-click finishes). `addPolyObj(tool, pts)` creates the room, `mkSlab` or `mkVoid`.
- Both are ordinary kinds in `KINDS` (`slabs → slab`, `voids → void`), so find/select/delete/copy/undo work unchanged. Point-list kinds are listed in `PTS_KINDS` (move, rotate, bbox, paste) and closed polygons in `POLY_KINDS` (vertex/edge handles, X/Y/W/D fields). **Add new pts-based kinds to these sets, not to scattered `kind === 'room'` checks.**
- 2D (`layerStrings` rooms layer): slabs under rooms, voids over them. Their hit shapes carry `data-low` (void 1, slab 2) so `pickDataId()` only picks them when nothing else is under the cursor — a large balcony must not steal clicks from furniture or room labels.
- 3D: free slabs are extruded `t` cm down from `elev + off + 0.2` (+0.1 per overlap level) so their top never z-fights the automatic slab; furniture whose centre is on a slab is raised/lowered by that slab's `off`. `voidHoles(voids, pts)` returns the voids that lie inside a polygon (edge-touching counts — stairwells snap to room corners) pulled 0.5 cm inward, and `build3D` adds them as `Shape.holes` to the automatic slab, the free slabs and the room floors of **that floor**. A void on floor N is the hole in floor N's slab, i.e. the ceiling of floor N-1. Voids that straddle a polygon edge are skipped (no CSG). **A void never cuts what is placed into it:** a slab or room that lies inside a void (`polyInPoly`, same outline included) fills the hole instead of being cut, furniture standing on such a room is not dropped by `voidDrop`, and in 2D `pickDataId` picks the smaller of overlapping low surfaces (`lowArea`; a filler slab with the void's outline wins).
- A floor with no walls gets no automatic slab from slabs/voids alone (`slabPolys` ignores them). Guard: `tests/slabs-voids.test.js` + a smoke check.

### Parametric stairs (issue #33)
- `stairSteps(o)` is the single source of treads for `k: 'stairs'`: `{ n, riser, tread, type, steps: [{ x, y, w, d, a, z, dx, dy, across, run, flight, landing }] }` in local plan coordinates (climbing toward −y on a straight stair, like the 2D arrow). `n = stairN(o)` = `stepN` or `round(h / 17.5)`, clamped 2–60 — legacy stairs without fields open as straight with a right-hand rail. L and U stairs get one landing (one riser); spiral sweeps 270° around a pole. **More types:** `lw` / `uw` = L / U with **winders** instead of the landing (3 × 30° on an L, 6 (4, 2 for few risers) on a U, wedges from the inner turn point clipped by `stairWedge`), `curve` = a 180° curved stair with an open well (no pole, inner radius 0.42 R, centre `(0, −d/2 + R)`). A step may carry `poly` (local corners); `stepCorners` returns it first, so 2D, walk mode (`walkSurfAt`), Revit and IFC need nothing else; spiral treads are true annular sectors now (`stairSector`). 3D extrudes `poly` steps (`prism` in the `furn3D` stairs case), thin open treads for `STAIR_OPEN` (spiral, curve). IFC export `QUARTER_WINDING_STAIR` / `HALF_WINDING_STAIR` / `CURVED_RUN_STAIR`, and the shared IFC-IMPORT block maps them back.
- `furnBody` draws every step with `stepCorners()` + a walking line and arrow; `furn3D` extrudes the same steps (open treads on a spiral) and builds railings from `stairRails()` (posts every third step, sloped handrail boxes with Euler order `YZX`). Up to ~45 meshes with rails on both sides.
- Panel: type, riser count, railing, riser / tread readout, `blondel(riser, tread)` (60–64 cm ✓, 57–67 ≈) and `stairfit` (h = wallH + 20, risers re-derived). Guard: `tests/stairs.test.js` + a smoke check.
- **Stair alignment & stairwells.** A library stair is created by `stairDefaults(o)` (in `updateGhost`, catalogue `stairs` without preset `extra` only; templates / MCP keep `mkFurn`): `h` = one floor pitch (`curFloorH() + 20`), `stepN = round(h / 17.5)`, straight `d = stepN · STAIR_TREAD` (28 cm). While placing, and when a single stair is moved (2D `doMove`, 3D drop), `stairSnap(o, p, { rev, prefRot, mode })` runs instead of `nearCenter` / `magnet`: near a door or arch (`isDoorOp` / `arch`) it centres the stair on the opening and climbs away from it, leaving the leaf width as a landing when the door swings to that side; between two parallel non-low walls (60–400 cm clear) it runs along them, sits against the cursor-side wall in `free` mode, and stops flush (or ≥ 40 cm short of) a crossing wall. `ui.stairW` (`stairWidthMode()` / `setStairWidthMode()`, `localStorage['fp_stairw']`, default `fit`) decides whether `w` becomes the clear gap / door width; `S` while placing (`placeSide` → `placingStair()`) and the panel button `stairwmode` toggle it; `R` (odd quarter turns of `placing.rot`) reverses the direction; a move keeps the closer of the two directions (`prefRot`). Rotation convention: `stairRotOf(ux, uy)` — an item climbs toward `(sin r, −cos r)`. **Stairwells:** `placeAt` calls `linkStairVoid(o)` for a stair that reaches the next floor (`stairReachesUp`), adding a `mkVoid` on `P.floors[fi + 1]` with `stair: <stair id>`; `commit()` runs `syncStairVoids()` so the void follows the stair's footprint (`stairVoidPts` = `furnCorners`), drops it when the stair is deleted and keeps it when the stair id lives on another floor (floor copies). **＋ Floor** links the stairs of the floor below. Panel: **⇔ Align to door / walls** (`stairalign`), **↔ Width** (`stairwmode`), **⬚ Open stairwell above** (`stairvoid`) or a ✓ readout, **⧉ Continue to the floor above** (`stairup`: copies the stair to the floor above at that floor's pitch, keeps its length, links the void, adds the floor if needed, one `commit()`).
- **3D size arrows.** `arrows3D()` (from `refreshSel3D`, `updateTools`, `syncWalkUI`) puts four cones (`T3.arr = { meshes, geo, mat }`, `depthTest: false`, rebuilt and disposed each call) on the sides of a single selected, unlocked, untilted furniture item in the select tool, at mid-height (`furnArrowSpots`). The 3D `pointerdown` picks them before furniture (`d3.rs` = `'w+' | 'w-' | 'd+' | 'd-'`, drag plane at the arrow's height, `furnLocalAlong` − grab offset); `pointermove` calls `furnResizeSide` (the opposite side stays put, 5 cm steps unless `Shift`, `poly` points scaled) and previews by scaling the item's group with a `#sizeTip` readout (`showSizeTip`); `pointerup` commits and rebuilds. Guard: `tests/stair-align.test.js` + the smoke check "stairs line up between walls…".

### Realistic look: materials, textures, lighting (issue #87)
- **Two looks, one scene.** The CAD viewport keeps its cheap, theme-styled Lambert materials. `realLook(S, sunVector, { mats, mood, contact })` turns the built scene into the realistic one and returns `{ restore(), dispose() }`; it is used by `render3DHQ` (styles `realistic` and `maquette`, restored + disposed in `finally`) and by `applyLive3D` (kept on `T3.live.real`, restored + disposed when the live view is re-applied or cleared). Nothing is stored in `P`.
- **Materials.** Every mesh material gets a cached `MeshStandardMaterial` twin chosen by `realClass(mesh)` (nearest ancestor with `opId` / `furnId` / `wallId` / `roomId` / `slabId` / `slab`): plaster walls 0.92, joinery 0.5, wood furniture 0.55, and `REAL_FURN` by catalogue type (porcelain, appliances, fabric, car paint, plants, screens). Transparent materials become glass, parts' Phong `gloss` / `metal` keep their meaning, `T3.ground` and shader materials are skipped.
- **Floors.** `floorTexture(kind, color, lt, C, real)` now draws richer finishes (parquet planks with their own tone, grain and bevelled seams; tiles with recessed grout; layered marble veins; carpet tufts; stone slabs) and, for those kinds, a height canvas → `t.fpBump` plus an inverted copy → `t.fpRough` (other kinds use the colour map as bump). Textures carry `fpKind` / `fpColor` / `fpLt` / `fpReal`. `realLook` always swaps in the **light, material-toned** variant (`lt = true, real = true`), so a render from dark theme equals one from light theme; `REAL_FLOOR` holds roughness and bump scale per kind. A room with `floor: 'none'` gets a neutral, lightly tinted screed instead of the translucent pastel fill. Extra textures are only uploaded to the GPU when a realistic material uses them.
- **Reflections.** `realEnv(sv)` renders the `makeSky` dome through `THREE.PMREMGenerator` into `T3.env` (cached per 4° of sun altitude, kept across rebuilds) and sets `scene.environment`. The PMREM target is RGBE-encoded, so the sky shader's raw sRGB output is linearised and passed through `linearToOutputTexel` there — without it every surface renders black.
- **Light.** Hemisphere colours and intensity and the sun intensity follow the sun altitude (`skyColors`), the fill light becomes a warm bounce; `RENDER_MOODS` (`ui.studio.mood`: `day` / `evening`, buttons `data-rs-mood`) adds a warm interior balance and a low sun. **Contact shading:** soft decals (`userData.fpDecal`, `contactTex`) under furniture and along wall bases, only where a slab lies under the strip (`slabPolys` + free slabs), skipped above 1200 walls + items.
- **Maquette style** (`RENDER_STYLES.maquette`): white card body with wood-toned floors, plus the same sun-aware light and contact shading (`mats: false`).
- Not built: user-placed light fixtures, bump detail on painted walls, roughness maps for the kinds without a height canvas. Guard: `tests/realistic-look.test.js` + a smoke check (same brightness from dark and light theme, no GPU leak across repeated renders, distinct roughness per surface, CAD scene restored).

### Model surfaces: sub-part materials & procedural textures (issue #93)
- **Tagging.** Inside `furn3D`, `doorLeaf3D` and the opening code in `build3D`, a colour may be a tagged object `sf(kind, colour)` (`surfOf(c)` reads it). `box` / `cyl` / `sph` accept it wherever they take a colour, so the model code stays one call per part. Only with `C.det`.
- **Real-world scale.** `surfGeo(type, ex, ey, ez, colour, C)` returns a unit box / cylinder / sphere whose UVs are multiplied by the part size ÷ `SURF_TILE[kind]` (cm per repeat; `tex:<id>` uses its `w` × `h`), quantised to 1/8 and cached in `C.geo`, so grain keeps its size on a 3 cm leg and on a 2 m table; the size stays in `mesh.scale`. Returns `null` (→ shared unit geometry) for untextured kinds, the stretched `rug` and `det` off. Extruded parts divide their cm UVs by the tile.
- **Realistic view.** `realLook`'s `std()` checks `userData.fk` first: `SURF[fk]` gives roughness / metalness, the kind's texture doubles as the bump map, and `ember` materials are returned unchanged (they glow).
- **Models.** Everything stays parametric on `o.w / d / h` and gated by `C.det`: sofas (legs, arm rolls, seat + tilted back cushions, pillows), chairs, office chair (5-star base, casters, armrests), tables with aprons, desk pedestal, true L-shaped `deskL`, `deskPC` computer desk (T-leg steel frame, arm-mounted landscape + portrait monitors with self-lit `ember` screens, glass-sided tower with fans and GPU, keyboard, mouse, mat; layout shared with its CAD plan symbol via `deskPCLayout()`), vanity mirror + stool, beds (frame, mattress, duvet drape + fold, two pillow rows, upholstered headboard, footboard), `bunk` (posts, two decks, guardrail, ladder), slatted `crib`, base cabinets (recessed toe-kick, fronts with reveals and pulls, stone / marble worktop), `sinkK` / `basin*` with **real holes** (`slabHoles` + `cavity`: the worktop is split around the bowl, walls and bottom hang below; sink and vanity carcasses are open so the bowl stays visible), gooseneck / mixer `faucet()`, stove (glass-ceramic top, grates, knobs, oven door + window, drawer), fridge / dishwasher / washing machine detail, `wc` (catalogue 38 × 72 × 78, `h` = tank top; an older item with `h < 60` is read as seat height, so old plans grow too) / `bidet`, `tub` (thick rim, sloped backrest, drain, deck mixer), framed glass `shower` with column and rose, plants / trees (pot, soil, multi-cluster canopy, bark), patterned `rug` with fringes, `car` (front = −y like the 2D hood; sloped glass via `slant()`, A / B / C pillars, wheels + hubs, lights, bumpers, seats), `pool` (coping, mosaic floor, translucent water, ladder), `fireplace` (recessed firebox, hearth, mantel, logs, glowing embers, flue). Openings: doors get raised panels on both faces, lever + rose on both sides, hinges and casings; windows get an inner frame, 1–3 sashes with profiles, double glazing, a handle on the opening sashes and a stone sill (`!det` keeps the old single pane). - **Light areas** layer (`layersVis.lightArea`, default off, Project ▸ Layers): `lightAreaSvg(f)` draws each lit fixture's reach (half of `lmToThree().d`, spots 0.32) on the canvas only, never in exports.

### Parametric roofs (issue #115)
- A catalogue item `roof` (`k: 'roof'`) carrying `roofType` (`flat | gable | hip | shed`) is a **parametric** roof; an item without it (IFC import) keeps its stored `faces` / `fbase` and nothing changes for it. Optional fields: `pitch` (°, 1–75), `ridge` (offset as a fraction of the depth across the ridge, ±0.45; gable / hip), `ridgeDir` (`'d'` = ridge along the depth; absent = along the width), `hip` (hip end run as a fraction of half the ridge-direction length; absent = equal pitch), `over` (eaves overhang cm), `th` (thickness cm), `rmat` (`ROOF_MATS`: tile / shingle / metal / slate / concrete / none). `roofP(o)` is the **only reader** (defaults: gable 30°, over 50, th 20, tile; flat: over 0, concrete). `w × d` is the footprint at the wall line, the eaves stick out by `over` and drop with the slope below the item base; `elev` = top of the walls. `o.h` is derived (`roofHeight` = rise + th): `cleanRoof` (panel, `normalizeProject` in both files) and `commit()` keep it current, so the panel hides the H field.
- **One engine, two copies:** the block between `/* ROOF-PARAM:BEGIN` and `/* ROOF-PARAM:END */` (`ROOF_TYPES`, `ROOF_MATS`, `isParamRoof`, `roofP`, `cleanRoof`, `roofPlanes`, `roofRise`, `roofHeight`, `roofClip`, `roofParamFaces`) is pure JS, pasted verbatim into `app.js` and `mcp/server.js`; `tests/parametric-roof.test.js` fails if they differ. `roofParamFaces` builds the roof as the **lowest of its planes** (one plane flat / shed, two gable, four hip) over the overhang rectangle: each plane's region is the rectangle clipped by the half-planes where it is below every other (`roofClip`), giving convex top (+th) and bottom faces plus edge faces on the outer boundary; `ridgeDir: 'd'` turns the result 90°, and the winding is flipped if needed so the signed volume in the right-handed `(x, −y, z)` frame is positive (Revit / IFC export). `roofFaces(o)` returns it for parametric roofs, so 2D (`roofTopFaces`, cached on the item), 3D (`roof3D`), sections (`rpoly`), attach to surface (#96, `surfFaces`), Revit and IFC export need no other change.
- 2D: `roofCourseSvg` adds one `<path>` of covering lines per roof (`ROOF_COURSE` spacing; tile / shingle / slate courses parallel to the eaves, metal seams along the slope, concrete a 60 cm grid; ≤ 80 lines per face) in `pal().furnStroke`, so dark, light and white-paper exports all read. 3D: `roof3D` writes cm UVs per face (u along the eaves, v up the slope) and, with detail on, uses `sf(ROOF_SURF[mat], colour)` → the procedural surface kinds `rooftile`, `shingle`, `seam`, `slate`, `roofcon` (`SURF`, `SURF_TILE`, `surfCanvas`), so the realistic view and the GPU cache treat them like every other surface.
- Panel (`isParamRoof`): type, pitch, ridge direction, ridge offset (%), hip end (%) + **↺ Equal pitch** (`roofhipauto`), overhang, thickness, covering (picking one also swaps the colour while it is still the previous covering's default, `ROOF_MAT_COL`), ridge height readout, **⌂ Fit to walls** (`rooffit` → `roofFitWalls`: bounding box of the solid walls' faces in the roof's own angle, `elev` = highest wall top; then every unlocked solid wall on the floor runs `attachWallTop`, so gable ends close). **Fit to walls** uses `roofWallFloor()`: the walls of the active floor, else of the floor below (an empty roof storey; `elev` = their top − the level difference, gable walls on that floor attach through `surfFacesOn`); with no walls at all it points to the draw tool. `mkFurn` → `roofDefaults` for a new catalogue roof (`elev = curFloorH()`); `magnet()` skips roofs; command `roof` places one. **🛖 Draw roof** (tool `roofd`, in `POLY_TOOLS`, no key): drag = rectangle, clicks = corners; `addPolyObj` → `roofFromPts(pts)` = `ifcRect` (minimum-area turned rectangle) → `w` / `d` / `rot`, `ridgeDir: 'd'` when deeper than wide (ridge along the long side), `elev` = `roofDrawElev()` (highest solid wall top under the footprint on this floor, else the floor below, else 0 on an upper floor / `curFloorH()` on the lowest); < 50 cm sides are refused. No wall is required anywhere. Mirror turns a `ridgeDir: 'd'` roof 180° (its shape is symmetric about local y), **⇄ Swap W/D** toggles `ridgeDir`. `PRESET_FURN_EXTRA` carries the fields.
- MCP: `add_furniture { catalogId: 'roof', roofType, pitch, ridge, ridgeDir, hip, over, th, rmat }` (elev defaults to the floor wall height), `update_object` runs `cleanRoof`, `summarize` prints `gable roof 30° tile, overhang 50 cm, height 251 cm`. Not built: polygon (L / U) footprints, dormers, skylights, gutters, mansard / gambrel. Guard: `tests/parametric-roof.test.js`.

### Wall faces: separate paint and finish per side
- Optional `c1` / `c2` (face paint) and `f1` / `f2` (finish: `WALL_FINS` built-ins or a project texture `tex:<id>` — wallpaper, tiles) on a solid wall. Face 1 is the wall-normal side `(-uy, ux)`, face 2 the other. `wallFace(w, i)` is the only reader (`col` falls back to `w.color`), `wallFaced(w)` says whether any face field is set; absent fields = the old single paint, so old projects are unchanged. `cleanWallFaces` (in `normalizeProject`) drops malformed values.
- Panel: `wallFacesHtml()` (a `<details>` that opens when a face is set): per face paint, finish and **🎨 Create / upload texture…** (`walltex` → `ui.txWall` = face; `addTexture` writes `f<face>` on the selected walls; `closeModal` clears it), **⇄ Swap faces** (`wallfaceswap`), **↺ Same on both faces** (`wallfacereset`). Faces are labelled by `wallFaceName()`: the room the face looks into ("Kitchen side"), else a compass direction (north = −y). The whole-wall **Wall paint** field and swatches clear `c1` / `c2`.
- 2D: `wallPaintSvg` draws each face's strip in its colour, with the finish pattern on top. 3D: `build3D` adds a thin `ShapeGeometry` skin 0.15 cm off each overridden face of every wall piece (around openings, sloped tops too); UVs are cm, so textures keep their real size (custom textures flip v so images stand upright); finishes are dropped with the detail level like floor textures. Mirror swaps the faces, split copies them, deleting a texture clears it from walls.
- Not built: per-face colours in sections / elevations, IFC / Revit export (they keep `w.color`), MCP tools to set faces (`update_object` passes the fields through untouched). Guard: `tests/wall-faces.test.js` + the smoke check "wall faces: …".
### Sloped surfaces (height points)
- Rooms and free slabs may carry `hp = [{ x, y, z }]` (plan cm; `z` = cm above the surface's normal top, ±`SURF_Z_MAX` 500, at most `SURF_HP_MAX` 64). Absent / all ±0 = flat, so old projects are unchanged. A point on a corner sets that corner, a point on an edge splits the edge, a point inside is an interior vertex; corners without a point stay at ±0. The surface is the triangle mesh through them (TIN), i.e. an even slope between points.
- **One pure block** `SURF-SLOPE` (`surfSloped`, `cleanSurfHp`, `surfTin` = ear clipping + interior point insertion + Delaunay flips that never touch boundary edges, `surfTinOf` (cached), `surfZAt`, `surfTriSlope`, `surfMaxSlope`). `surfTinOf` / `surfZAt` are the only readers. `xfHp(o, g, fn)` moves the points with every polygon transform (move, rotate, mirror, scale, panel X/Y/W/D, nudge, paste, 3D drag); layout poses (`snapPose`) carry `hp`; a dragged corner takes its point along; `cleanSurfHp` runs in `normalizeProject`.
- 3D: `surfGeo3D(o, t, holes)` builds the top (group 0, cm UVs so finishes keep their size) plus a constant-thickness bottom and sides (group 1); free slabs use it with `t`, rooms for the finish (`t = 0`) and the room slab block. A room that dips below ±0 is cut out of the automatic floor slab (`dipRooms`, through the `glassCuts` list) so its own sloped block shows. Furniture on a sloped slab / room sits at `surfZAt` (`furnOff`); walk mode stands on it (`walkGroundAt`). Glass rooms / slabs stay flat (the panel is hidden for them).
- 2D: `slopeSvg(o)` (in the room-labels layer, exported too): a marker and a signed level per point (`fmtSurfZ`), dashed inner fold lines of the mesh and a downhill arrow with its % on each large enough triangle.
- Panel: `slopePanelHtml(o)` (rooms and slabs, single selection): one height field per point (`data-k="hp"`), 🗑 (`hpdel`), **＋ Add point** (`hpadd` → `ui.hpAdd`; the next select-tool clicks on the surface add points, snapped; `Esc` / ✓ Done ends it), **⛶ Points on corners** (`hpcorners`), **↧ Flatten** (`hpflat`) and the steepest slope. Point handles `zp<i>` drag a point (not shown for corner points, they move with the corner).
- Not built: slopes in sections / elevations, IFC / Revit export (flat), MCP tools (`update_object` passes `hp` through), sloped automatic floor slab, sloped glass. Guard: `tests/surface-slope.test.js` + the smoke check "sloped surfaces: …".

### 3D ground surface, datum & terrain (#147, #148, #149)
- `P.ground = { kind?, color?, scale? }` (optional, project-wide, undoable; absent = `auto` = the old look: theme colour in the CAD view, grass in the live view and sky renders, paper in white-backdrop renders). `kind` ∈ `GROUND_KINDS` (`grass soil sand gravel asphalt concrete stone snow water studio none`) or a project texture `tex:<id>`; `color` = tint, `scale` = cm per texture repeat (`GROUND_TILE` defaults, 20–5000). **One block, two copies:** `GROUND-PARAM` (`groundP` = the only reader, `cleanGround` drops invalid and default values) is pasted verbatim into `mcp/server.js`; `tests/ground-surface.test.js` compares them.
- `groundMat(mode)` builds the material: `'cad'` (Lambert, darkened in dark theme; `auto` → `null` = the old `mat()` colour), `'real'` (Phong + bump, used by `applyLive3D` and sky renders; night multiplies the colour), `'paper'` (white-backdrop renders). It returns a new material each call; the caller disposes it (`extraMats` in `build3D`, `T3.live.mats`, `studioGround` in `render3DHQ`). `none` sets `T3.ground.visible = false`. Textures: `groundCanvas(kind)` = one tileable 512 px grey pattern per kind (module cache, never disposed), tinted by the material colour; its **alpha channel** holds an independent large-scale noise (160–255). `groundAntiTile(m)` replaces `map_fragment`: the map is read at two scales mixed by that noise, and two very low-frequency noise reads add light / dark regions, so the 400 m plane shows no tile grid from above; `texelColor.a` is forced to 1. Custom textures (`tex:`) use their green channel instead (no `GROUND_MACRO_A` define).
- **Horizon:** `makeSky`'s `under` uniform is 0 while the ground is visible, so the sky below the horizon is the fog colour and the plane's far edge never shows as a line.
- **Plinth, excavations, section earth, outdoor walking (#148).** `P.ground.plinth` (cm, 0–`GROUND_PLINTH_MAX` 300; default `GROUND_PLINTH_DEF` 20 = the old look) = how far the ground lies below ±0.00. `groundDatum3D()` = ±0.00 in 3D (the lowest visible floor when only upper floors show), `groundY3D()` = datum − plinth − 1 (never coplanar with the 20 cm slab's bottom), `groundFloorIdx()` = the lowest floor at or above ±0.00. Above 20 cm `build3D` extrudes a **plinth skirt** (`userData.plinth`) under that floor's `slabPolys` from −20 down to the ground, and `archPrims` adds the same plate, so sections cut it and elevations show it. `groundCuts(world)` lists the excavations `{ pts, bot }` (underground floors' slab outlines, pit voids; `bot` = the slab bottom) and merges touching / nested ones (`segX` edge test, `polyUnion` = raster union with only outer loops; disjoint outlines stay exact); `groundHoles3D()` uses it for the ground holes and `earthSides3D()` builds vertical earth faces along each hole from the ground to `bot` (`fpDecal`: not pickable, the realistic look leaves it alone; the material's `polygonOffset` lets a basement wall's outer face win where they coincide). `archSvg` draws the ground line at −plinth and an **earth hatch** (`#earthH`, white base) below it, after the faces beyond and before the cut bands, so nothing behind the earth shows; in sections the excavation intervals along the line stay open down to their `bot`; the level labels on the left stay clear. Walk mode: `walkLevels` gives the ground-floor level `gnd` (the ground relative to that level); `walkGroundAt` stands on it outside the building's footprint (automatic slab, rooms, free slabs) and treats the floor as rising from it (a high plinth blocks, 20 cm steps up). Not built: islands inside a merged excavation, earth on terrain slopes (#149), plinth in IFC / Revit export.
- **Terrain (#149).** `P.ground.tp = [{ x, y, z }]` (≤ `GROUND_TP_MAX` 200 sparse height points, plan cm, `z` = cm relative to ±0.00, ±`GROUND_TZ_MAX`), `ci` (contour interval from `GROUND_CI`, default 50), `snap` (outdoor items stand on the terrain). Only points are stored, never a mesh; no points = flat ground and no extra geometry. `terrainBox()` = every floor's content + the points, 20 m margin, 1 m grid; `terrainRing()` = the points alone + 20 m. `terrainObj()` (cached on `terrRev` — bumped by `commit()` and live collab patches — + the `P` object + `P.ground`; never on `hi`, which stops moving once the undo stack is full) = `{ pts: box corners, hp: points as height above the natural ground (−plinth) + natural-ground samples along the ring, base: −plinth, box }`. The ring samples keep the shape a function of the points only: content far away grows the box but only adds flat ground beyond the ring, i.e. a SURF-SLOPE surface whose edges stay at the natural ground, so it meets the flat plane without a seam; `terrainZ(x, y)` is the only height reader (±0.00-relative; outside the box = −plinth). **3D:** `groundMesh3D(material, cuts)` cuts the box out of the plane and adds `terrainMesh3D(o, cuts)` as its child (TIN through the points plus points every 1.5 m along each cut outline, triangles whose centroid is in a cut dropped, plane-compatible UVs; the child's `material` is a getter returning the plane's, so the CAD / live / render swaps and `kind: none` apply to it unchanged). On terrain `build3D` also cuts the ground-floor footprint (`gCuts`), and `earthSides3D(cuts, top, mat)` takes a height function so earth sides run from the terrain surface to the excavation bottom. **2D:** `terrainLayerSvg(f, live)` → `terrainSvg` on the ground floor only (rooms layer, exported too; layer toggle `layersVis.terrain` shown once points exist): minor / major (every 5th) contours by marching triangles, major labels, spot heights (`fmtLevel`), `pal()` colours. **Editing:** `setTool('terrain')` (2D only, `FP3D_2D_ONLY`; reached from **✏ Edit terrain** in the project panel or the `terrain` command — no free letter key): a click adds a point at the current terrain height (and focuses its height field), dragging moves one (`ui.drag.type = 'tp'`, commit on release), `Delete` removes `ui.tpSel`; `terrainPanelHtml()` replaces the panel while the tool is on (presets `terrainPreset('flat' | 'slope' | 'hill')`, **🏠 Level the building pad** = `terrainPad()`, contour interval, outdoor snap, one height field per point `data-k="tp"`). **Sections / elevations:** `archSvg` samples `prof(s)` (sections: along the cut line; elevations: the highest ground along the view direction), draws the earth as one path and the ground line as a sloped path broken at excavations. **Walk:** the ground-floor level carries `tz`; `walkSpawnZ` also tries that floor alone with no height cap, so a start on a hill above a storey works. **Plinth:** changing it shifts every point by the same amount, so the relief stays relative to the natural ground. **Outdoor items:** `terrainDrop` in `build3D` (only with `snap`): ground-floor items outside the footprint and the rooms sit at `terrainZ`, plus `2 + curb` on a visible non-parcel zone (`zoneLiftAt`, same as `zoneTopRel`). **IFC:** `revitExport` writes `terrain.faces` (world feet); the writer adds an `IfcGeographicElement` `.TERRAIN.` (surface model) contained in `IfcSite` (the importer ignores it). MCP: `set_terrain { points, add, clear, interval, snap }`, `summarize` prints the range. Not built: editable terrain bounds, survey CSV / XYZ import, terrain in the Revit add-in, constrained edges (cut outlines are approximated by dense points).
- Panel: `groundPanelHtml()` in the project panel (`data-k="ground"`, plinth field, terrain summary + **✏ Edit terrain**, **↺ Default tint / scale** = `groundreset`). MCP: `set_ground { kind, color, scale, plinth }`, `summarize` prints `3D ground: …, plinth N cm`. Guard: `tests/ground-surface.test.js` + the smoke checks "3D ground surface (#147): …", "ground datum (#148): …" and "terrain (#149): …".

### Ramps (issue #58)
- Catalogue item `ramp` (`k: 'ramp'`): `w` = width, `d` = horizontal length, `h` = rise. Like stairs it climbs toward local −y (low end at +d/2). `rampType(o)` (`RAMP_TYPES`: accessible / vehicle / landscape, default accessible) and `rampRail(o)` (`railing`, default `both`, `none` for vehicle ramps) are the only readers of the optional fields, so legacy-free defaults need no `normalizeProject` work.
- `rampSlope(o)` → `{ pct, ratio, deg, cls }`; `cls` (`RAMP_CLS`): ≤ 6 % `ideal`, ≤ 8 % `access`, ≤ 15 % `vehicle`, else `steep`. The panel shows % / 1:X / degrees with a coloured badge; an accessible ramp steeper than 8 % offers **↔ Lengthen to 8 %** (`rampfit`, keeps the rise).
- 2D (`furnBody`): outline, anti-slip lines, curb lines (accessible), rail lines, an up arrow and a `%6.7 · ↑40` label (exported too). 3D (`furn3D` case `ramp`): one `ExtrudeGeometry` wedge, 5 cm curbs (accessible), grooves (vehicle, detail only), posts about every 150 cm and handrails at 90 cm (+ 70 cm on accessible ramps) parallel to the slope. `isStructFurn` includes ramps for the floor underlay.

### Height above floor (issue #61)
- Furniture may carry an optional `elev` (cm above the floor, ±`FURN_ELEV_MAX` = 500; negative = below the floor, e.g. an IFC element from a merged lower level). `furnElev(o)` is the only reader (absent / 0 = 0), so old projects need no default. `build3D` lifts the furniture group by it on top of the free-slab offset (`fy = elev + furnOff(o) + furnElev(o)`); `g.userData.elev` already carries it, so `moveFurn3D` and 3D drags keep the height.
- Wall-mounted catalogue items get a default from `CAT_ELEV` in `mkFurn` (only when `o.elev == null`, so a preset's own value wins): `tvw` Wall TV 80, `art` 120, `shelfW` 150, `ac` 220, `cabU` Wall Cabinet 145, `wmirror` 110. The floor-standing `tv` unit is deliberately not in it.
- 2D (`furnSvg`): a raised item is drawn dashed (the usual "above the cut" convention) with a `▲ +80` tag in front of it (exported too). Panel: **Height above floor (cm)** for every item except stairs and ramps; `applyProp` clamps it. `PRESET_FURN_EXTRA` includes `elev`.
- MCP: `CAT_ELEV` and the six items are mirrored in `mcp/server.js`; `add_furniture` takes `elev` (−500–500), `list_catalog` and `summarize` show it. Rooms have no offset on purpose (free slabs have **Level offset** for platforms).

### Wall base offset
- Walls may carry an optional `elev` (cm from the floor level, ±`WALL_ELEV_MAX` = 500, negative allowed); `wallElev(w)` is the only reader (absent = 0), so old projects need no default. Openings' `sill` stays relative to the **wall base**.
- Used by `build3D` (wall group y, hinge pin, opening groups' `userData.elev`; corner fillers cover only the height range shared by the joined walls), `archPrims` (`WE = E + wallElev(w)` for faces, cut bands and opening holes), `walkSegs` (a wall starting at eye height or ending ≤ 30 cm above the floor does not block), `realLook` (no contact strip under a raised / sunk wall) and `wallDimSvg` → `wallTag(w)` (`· ▲ +220` / `· ▼ −50` after the length, exported too). Panel field **Base offset (cm)**, `applyProp` clamps and rounds it. MCP: `add_wall` / `update_object` take `elev` (−500–500), `summarize` prints `base ±N`. Guard: `tests/furn-elev.test.js` + a smoke check.

### Per-floor wall height (issue #59)
- `Floor.wallH` is optional: `floorH(f)` = `f.wallH` or `P.wallH`; `curFloorH()` for the active floor. `mkWall` (and the MCP `mkWall` / `add_rect_walls`) default new walls to it; `add_floor` accepts `wallH`.
- Floor pitch is `floorH(f) + 20` unless a floor has its own level (below): `floorElev(i)` is the single source for `archPrims`, `show3D`'s focus elevation, `walkElev` and `build3D` (`elev = v3dElev(fidx)`). `floorPitch(i)` = `floorElev(i + 1) − floorElev(i)` (the top floor: height + 20) is what stairs (`stairDefaults`, **Match storey height** via `curFloorPitch()`, `stairReachesUp`, **Continue to the floor above**) and walk mode (`walkLevels`, floor changes) use. **Never use `P.wallH + 20` or `floorH(f) + 20` for stacking again.**

### Basements & floor levels
- `Floor.lvl` (optional, cm, ±`FLOOR_LVL_MAX`; `floorLvl(f)` reads it) = the floor's level (±0.00 = ground, negative = underground). `floorElev(i)` uses it when set, else stacks on the floor below (first floor ±0); `floorElev(P.floors.length)` is the level above the top floor. Old projects have no `lvl`, so nothing moves. `normalizeProject` (both files) rounds / clamps it and drops non-numbers.
- **＋ Basement** (`#floors [data-fa="addb"]` → `addBasement()`): pins the current lowest floor's level (`lvl` = its current elevation, so the ground floor stays at ±0.00) and inserts a floor at index 0 with `lvl` = that − (`P.wallH` + 20); one `commit()`. Floor tabs show `fmtLevel` (`.flv`) once any floor has a `lvl`; every tab's title has its from → to levels.
- Project panel: `floorLevelHtml(f)` (**📏 Floor level**): `lvlB` (floor level, m) writes `f.lvl`, `lvlT` (ceiling level, m) writes `f.wallH` = top − level (clamped 100–800, cleared when equal to `P.wallH`); an overlap with the floor below shows a warning; `floorlvlreset` deletes `lvl`.
- 3D ground: `groundMesh3D()` (y = `groundY3D()` = real ±0.00 when the lowest visible floor is underground, else the old −21 under it); `groundHoles3D()` cuts the slab outlines of visible underground floors and pits that reach below the ground (largest first, overlapping ones skipped); without holes it is the old `PlaneGeometry`. Sections / elevations extend the drawing below the ground line (`archSvg` `zLow`). ### All-axis rotation (parts and furniture items)
- **Parts:** optional `rx` / `ry` (degrees, normalised 0–360, absent = upright) tilt a part about its own x / y axis; together with `rot` the part turns about its **centre** `(x, y, z + h/2)` as `R = Rz(rot) · Ry(ry) · Rx(rx)`, so `z` is the bottom only while the part is upright. The shared PARTS-ENGINE block holds the maths: `partRotM(rx, ry, rz)` (3 × 3, plan frame), `partTilted(q)`, `partCloud(q)` (surface sample points in item-local cm), `partHull(pts)` (convex hull) and `partBounds()` (cloud extents; exact for spheres; the old exact code for upright parts is unchanged). Validation, magnets, Fit box and floating-part checks all go through `partBounds`.
- **Rendering:** 3D `parts3D` sets `rotation.set(−rx, −rot, −ry, 'YZX')` and multiplies the cylinder's lying pre-rotation after it (plan y = Three z, so every angle is negated; `tests/axis-rotation.test.js` proves the two matrices match). Tilted extrusions are re-centred first. 2D `partShapeSvg` and the studio front / side views draw the hull of the projected cloud; tilted parts lose the size handles (sizes come from the panel). Studio panel: Turn (Z), Tilt X, Tilt Y, **⤾ X 90°** / **⤿ Y 90°** (keep the bottom where it was), **↺ Upright**; **Put on floor** / **Sit on top** use the real bottom.
- **Furniture items:** optional `rx` / `ry` on the item (`furnTilted(o)`; never stairs, ramps or roofs — `NO_TILT_K`). `build3D` wraps the item in `furnTiltGroup()`: it turns about mid-height and is lifted so its lowest corner rests on the floor (+ `elev`), e.g. a cabinet laid on its back. 2D draws the tilted footprint hull (`furnTiltSvg` / `furnTiltPts`, parts included), `furnCorners` returns that footprint, and the corner resize handles are hidden while tilted. Panel: Tilt X / Tilt Y fields, ⤾ / ⤿ 90° and ↺ Upright (`data-act="tiltx|tilty|upright"`). Mirror negates `ry` (items and parts), Swap W/D keeps tilts. `PRESET_FURN_EXTRA` carries `rx` / `ry`.

- `#bIfc` (⬇ IFC, command `ifc`) → `downloadIfc()` = `ifcFromExchange(revitExport(P))`: the IFC writer reuses the Revit exchange object, so both exports share one geometry path (feet, y up) and the writer only converts to **metres** and STEP. Colours: one `IfcSurfaceStyle` + `IfcSurfaceStyleRendering` per colour (glass = 0.6 transparency) via `IfcStyledItem`. **Own round trip:** every item carries `FloorPlanner.FloorPlannerItem` = its own settings as ASCII JSON (`rvItemParams(o)`: the item minus `id x y rot elev layer grp lock`, exchange field `fp`); the importer (shared IFC-IMPORT block, before the column / component / roof / stair / ramp loops) rebuilds such elements from it and takes only position, turn and height from the IFC placement, so a re-imported plan keeps sizes, colours, types, parts, stair / roof / lamp fields exactly (before, catalogue items were re-guessed from their mesh: beds came back 100 cm high, colours from the first mesh colour, shelves as parts). ### IFC import (Revit / BIM)
- **One parser, two copies.** The block between `/* IFC-IMPORT:BEGIN` and `/* IFC-IMPORT:END */` is pure JS (no DOM, no globals) and is pasted **verbatim** into `app.js` and `mcp/server.js`; `tests/ifc-import.test.js` fails if they differ. `ifcToProject(text, { uid, L, colors, name })` → `{ project, stats }` (`stats`: `schema, floors, walls, ops, rooms, slabs, voids, skipped`). Entry points: `openPlanFile(file)` (`#fileOpen`, which now accepts `.ifc`, and a file drop on `#stage`) → `importIfcText()` → `newTabSlot()` + `loadProject()`; MCP `import_ifc { path }`.
- **Reading STEP.** `ifcParse` makes one pass over `DATA;` and indexes `#id → { t, s, e }` plus `byType`; parameters are parsed on first use (`ifcValues`: `$`/`*` → null, `#12` → `{ r }`, `.X.` → `{ e }`, `TYPE(v)` → `{ tv, v }`, strings via `ifcStr` for `\X2\ \X\ \S\`). ifcXML, ifcZIP and non-STEP text throw. Units: `LENGTHUNIT` (SI prefixes, `IfcConversionBasedUnit` such as feet) → cm, `PLANEANGLEUNIT` → radians. Plan `x = X`, `y = −Y`.
- **Geometry.** `place()` resolves local placements / axis placements / transformation operators to `{ o, x, y, z }` frames. `solid()` collects world points from extrusions (rectangle, circle, arbitrary, derived and composite profiles), the **first operand** of boolean results (the second too only for `UNION`), mapped items, faceted breps / shells, polygonal and triangulated face sets and bounding boxes; vertical extrusions and the largest bottom brep face also give a footprint polygon. Representations used: `Axis`, `FootPrint`, `Body` (and `Box` as a fallback).
- **Walls.** The body's extent across the axis gives the thickness **and** the true centreline (Revit's location line may be a face); then material layer sets, then 20 cm (10 for curtain walls). Curved axes (trimmed circles) become segments every 10°; a wall without an axis uses `ifcPca` (minimum-area rectangle of the convex hull). Curtain walls take the points of their aggregated children; stacked-wall parents whose parts are walls are skipped. `ifcJoinWalls` then moves nearby ends to the intersection of the two centrelines (corners) or extends an end that stops short of another wall's body (T), so `wallJoints()` closes them.
- **Openings.** `IfcRelFillsElement` / `IfcRelVoidsElement` link door / window → opening → host wall; the opening's body gives `d`, `w`, `h` and `sill` (relative to the wall's base), with the door / window body and `OverallWidth/Height` as fallbacks and the nearest wall (≤ `t/2 + 60` cm) when there is no relationship. Type: windows → `window`; doors → `slide` / `double` from the operation type, else `double` when ≥ 150 cm wide; unfilled openings → `arch` (or `window` with a sill). Swing side is always the default (`side: 1, flip: 0`).
- **Helper levels are merged.** Revit models often carry reference levels 30–50 cm apart (finish, parapet, sill). Storeys closer than `IFC_LEVEL_MERGE` (100 cm = `FLOOR_H_MIN`, the smallest floor the app can show) form one floor (`opts.mergeLevels: false` disables it); the floor takes the elevation and name of the member level that contains the most elements, every member id maps to it in `SBY`. Nothing loses its height: a wall keeps its real base as `elev` (the first piece of a multi-storey wall keeps its own bottom, not the storey's), furniture / columns / stairs get a signed `elev`, slabs their `off`. `stats.levelsMerged` counts the dropped levels. Without this, walls running from L1 to L4 / L6 / L10 were sliced at every helper level into 30–50 cm stubs on separate floors (the "gappy walls" of the atolye model).
- **Clipped walls.** `IfcBooleanClippingResult` / `IfcBooleanResult` `DIFFERENCE` with a half space (`IfcHalfSpaceSolid`, `IfcPolygonalBoundedHalfSpace` — Revit's "attach top to roof") runs `clipHalf()`: the first operand's points on the removed side (inside the bounding polygon) are dropped vertically onto the clip plane, so the wall height follows the clipped top. Vertical clip planes are ignored.
- **Rooms, slabs, voids, floors.** `IfcSpace` → room (name = `LongName`, else `Name`); `IfcSlab` except `ROOF` → free slab (`t` = depth, `off` = top − storey elevation); openings in slabs → voids. **Storeys by elevation (#72):** `storeyOf(id, z)` trusts containment / aggregation only while the geometry lies inside that storey's band (`z ≥ storey − 30` and `< next storey − 30`), else the storey at that elevation — Revit elements hosted on an upper level with a negative offset land where they are. `spanOf(id, z0, z1, h)` returns one piece per storey a wall or column overlaps by more than 30 cm (the piece under a storey stops 20 cm below it, like the floor pitch); openings pick the piece whose height range holds them. Empty storeys are dropped.
- **Columns, railings, components (#72, #73).** `IfcColumn` → catalogue `column` (round footprint) or `colSq` (rectangle, `ifcRect()` = minimum-area rectangle → `w`, `d`, `rot`), else a `shape` polygon, one per storey spanned, with `elev` when its base is off the floor. `IfcRailing`, and proxies whose name / type says railing (`RAIL_RX`: railing, handrail, korkuluk, fence…; Revit often exports railings as proxies), become `railing` (or `fence`) walls (6 cm default, ≤ 10 cm, sloped stair rails → 100 cm). **Path:** `railSegs()` clusters the long plan edges of the railing's faces by direction and offset (≤ 15 cm apart, same line), so one-piece L / U / bent railings come in as several joined segments (`ifcJoinWalls` closes the corners) and the glass / rail thickness becomes `t`. **Style:** `IFC_RAIL_STYLE` word matches on names and materials (cam / glass → glass, kablo / cable / halat → cable, parapet / beton → solid; a transparent style → glass). Railings inside a stair or ramp are not walls: `railInfo()` sets the stair's / ramp's `railing` side (left / right / both, by the rail centre against the flight frame) and `rs`. `IfcBuildingElementProxy`, `IfcFurnishingElement`, `IfcFurniture`, `IfcSystemFurnitureElement`, `IfcSanitaryTerminal`, `IfcElementAssembly` (children of an imported assembly are skipped) → `type: 'shape'`, `k: 'poly'` with the plan footprint, `h` = height and `elev`. A component made of **2–64 separate solids** (`leavesOf`: body items, mapped sources and aggregated parts) becomes **one multi-part item** (`partsItem`: a box part per rectangular solid, an extrude part otherwise, each with its own `z` / `h` and style colour; `pbase` = the item box, `partsV: 1`), so e.g. Revit box-profile bands on several floors are no longer extruded into one tall block. Component footprints use the minimum-area rectangle (`ifcRect` → true `w` / `d` and `rot`, `pts` local to it); a footprint that the 5 mm outline cleanup collapses (2 mm steel sections) falls back to the body hull, and only footprints under 0.5 cm² are skipped. I / T / L / U / C / Z profile defs give their outer rectangle. **Proxy windows / doors:** Revit often exports window and door families as `IfcBuildingElementProxy` with no `IfcRelFillsElement`; a proxy whose body centre lies in an unfilled opening (±10 cm, `proxyFill`) becomes that opening's window / door (name says door / kapı → door, window / pencere → window, else by sill), takes its colours, and is not imported again as a shape. Names drop Revit's trailing `:123456` id. `stats` adds `columns`, `railings`, `components`, `roofs`, `stairs`, `ramps`.
- **Roofs.** `IfcRoof` (its own body, else its aggregated parts) and `IfcSlab` `ROOF` not inside an imported roof → one furniture item `{ type: 'roof', k: 'roof', faces, fbase, elev }`. `solid()` takes an optional `fc` array and emits face polygons (extrusions: base, top and sides; breps: outer bounds only; polygonal / triangulated face sets); `facesOf(id)` collects them for the body. More than `IFC_ROOF_MAX_FACES` (600) faces → the hull of the footprint extruded to the roof height. App side: `roofFaces(o)` scales the faces by `w / d / h ÷ fbase` (so resize and group scale need nothing else), `roofSvg()` draws the upward faces lowest first, `roof3D()` triangulates each face in its own plane (`THREE.ShapeUtils`) into one mesh, `mirrorObjs` / **Swap W/D** transform the faces, `archPrims` projects them as `rpoly` prims (sections: only faces beyond the cut), `PRESET_FURN_EXTRA` keeps `faces` / `fbase` / `elev`; the parts studio is hidden for roofs.
- **Ramps.** `IfcRamp` (one catalogue `ramp` per `IfcRampFlight`, else the whole ramp) and flights without a ramp → `k: 'ramp'`. Direction and frame as for stairs (shared `climb()`); `h` = rise of the **top surface** between the two ends (highest point in the end 10 % at each end, so the slab thickness does not count), `elev` = top of the low end; `rampType` `vehicle` when a name says car / vehicle / garage / parking / otopark / araç or the ramp is ≥ 250 cm wide, else `accessible`; `railing` both / none from the railings inside it. Switchback ramps come in as several straight ramps.
- **Colours & materials.** `styleOf()` reads `IfcSurfaceStyleRendering` / `Shading` colour + transparency (through `IfcPresentationStyleAssignment` in IFC2x3). `itemStyle` maps geometry items (`IfcStyledItem.Item`) to styles, `matStyle` maps materials through `IfcMaterialDefinitionRepresentation`; `matsOf()` opens layer set usages, layer / profile / constituent sets and material lists. `looksOf(id)` walks the body items (into mapped sources and the first boolean operand — Revit styles the mapped **source** items), falls back to material styles, and returns `{ col: first opaque colour, glass: any transparency ≥ 0.5, names }`; `looksDeep` tries aggregated parts. Applied: wall paint `w.color` (not for curtain walls, and only when `!ifcNeutral(col)`, so grey / white Revit defaults keep the theme wall colour), railings always; doors `mat` from `IFC_DOOR_MAT` word matches (glass / metal / wood; glass-only styles → glass) and leaf `color`, windows `frameCol`; slabs `floor` from `IFC_FINISH` word matches (Turkish and English names: beton / betonarme / gazbeton → concrete, parke → wood, mermer, seramik, taş, cam…, glass styles → glass) and `color` when not neutral; columns, components, roofs, stairs and ramps `color`. Not imported: textures / images, rooms' colours (rooms keep the palette).
- **Revit fidelity (#88).**
  - *Footprints:* `footFrom(faces, foot)` takes the horizontal faces at the bottom of a brep / `IfcPolygonalFaceSet` / `IfcTriangulatedFaceSet`, chains the edges used by only one face (`ifcOutline`) and pushes each outer loop as a footprint and each loop inside one as `foot.holes` (→ `g.holes`). Concave L / U slabs and spaces no longer fall back to the convex hull, and a triangulated bottom becomes one polygon. `IfcIndexedPolygonalFaceWithVoids` inner loops and brep inner bounds are holes too. `IfcArcIndex` segments of `IfcIndexedPolyCurve` are tessellated (`ifcArc3`); `IfcRevolvedAreaSolid` contributes its swept points.
  - *Slab voids:* inner curves of `IfcArbitraryProfileDefWithVoids` and the footprint holes become `voids` (`shaft`, ≥ 400 cm²) when the slab has no `IfcRelVoidsElement`.
  - *Doors:* `side` = which side of the wall the door's local +Y points to; `flip` from `OperationType` LEFT / RIGHT (hinge on the left = local −X as seen along +Y) compared with the wall direction. `doorOps(fid)` reads the operation from the door and its type / style. A door or window aggregated under a curtain wall (no opening element) is matched against that curtain wall first.
  - *Curtain walls:* vertical `IfcMember` children are counted along each segment (12 cm from the ends, 5 cm clusters) → `mulN`, omitted when it equals the default 120 cm module.
  - *Catalogue matching:* `opts.catalog` (id → catalogue def; both call sites pass `BYID`). `ifcCatKey(names)` checks compound names first (`IFC_CAT_PHRASE`), then single words (`IFC_CAT_WORD`, **last** matching word wins: "Dining Table", "Yatak Odası Dolabı"); the tables use the `ifcWords` alphabet, not `\w`, so Turkish suffixes match. `sofa` / `bed` / `table` resolve to a variant by size. `catItem()` takes the rotation from the placement's X axis (IFC +Y = back = local −y in the app), the size from the body in that frame, and falls back to the minimum rectangle when the frame is not aligned with the body; the long side is turned to the catalogue's long side. Only furnishing / sanitary / flow-terminal / appliance entities are matched — proxies and assemblies stay `shape` / multi-part. `IFC_COMPONENTS` now includes `IfcFlowTerminal`, `IfcElectricAppliance`, `IfcAudioVisualAppliance`; an unrecognised flow terminal (diffuser, sprinkler) is skipped.
  - *Rooms:* floor finish from a property set (`propOf(id, IFC_FLOOR_PROP)`: FloorFinish / Zemin Kaplaması), else a related `IfcCovering` `FLOORING` (`IfcRelCoversSpaces` or containment), else a flooring covering whose centre lies in the room. A storey with walls and no room runs `ifcRooms(walls)`: centrelines are split where they cross or touch (an end within half a wall of another wall counts), dangling ends are pruned, the inner faces of the planar graph (≥ 1 m²) are traced and inset by half the median wall thickness (`ifcInset`).
  - *Alignment:* the length-weighted dominant wall direction (mod 90°) is turned onto the plan axes before the shift when it is at least 0.5° off and the walls agree (concentration > 0.6); `opts.align: false` disables it. `stats` adds `matched`, `roomsDetected`, `rotated` (degrees).
  - Not built: ellipse / spline curves in profiles, door swing for doors without a usable placement, finishes from material layers of the slab under a room, IFC export. Guard: `tests/ifc-import.test.js` (`88-*`, fixture `tests/fixtures/revit-fidelity.ifc`) + a smoke check.
- **Stairs.** `IfcStair` (and flights without a stair) → catalogue `stairs` (`k: 'stairs'`). The first flight's climb direction gives `rot`: Revit exports no walking line and no oriented flight placement, so `climb()` fits a plane `z = a·x + b·y` to the body points and takes the rectangle side the slope rises along (a short flight — 3 risers, 55 cm run, 255 cm wide — therefore does not turn 90°); without a usable slope (a single step) it falls back to low → high end along the long axis (local −y = up). `w` / `d` / centre are the extents in that frame; `stairType` from `ShapeType` / `PredefinedType` (straight / quarter → `l` / half → `u` / spiral), else from the angle between the first and last flight; `stepN` = sum of `NumberOfRisers`, else h / 17.5; `railing` = both / right / none from the railings inside the stair, which are **not** imported as walls; landings and other stair or roof parts are not imported as slabs or components. The app's L / U stairs turn one way only, so a stair turning the other way keeps its footprint and first flight but its turn is mirrored. **Raised floors:** an item's `elev` is stored relative to the free slab under its centre (the last containing slab, the same rule as `build3D`'s `furnOff`), because the app adds that slab's `off` in 3D, sections and exports — without this, furniture on a Revit 45 cm raised floor floated at 90 cm and a pendant moved up a storey on re-import. A storey whose IFC slabs hold ≥ 60 % of its room centroids (no rooms: slab area ≥ half the wall box) gets `noSlab: true`, so the automatic floor slab no longer doubles the imported one. Coordinates are shifted so the plan starts near 0 (multiples of 1 m); `P.wallH` = median solid wall height and `Floor.wallH` = storey pitch − 20 when it differs. Not imported: textures / images, full 3D meshes of components (extruded footprints).

### DXF import (AutoCAD / CAD drawings)
- **One parser, two copies.** The block between `/* DXF-IMPORT:BEGIN` and `/* DXF-IMPORT:END */` is pure JS (no DOM, no globals) and is pasted **verbatim** into `app.js` and `mcp/server.js`; `tests/dxf-import.test.js` fails if they differ. It uses the IFC-IMPORT helpers `ifcJoinWalls`, `ifcRooms`, `ifcCatKey` and `ifcCleanPoly`, so it must stay **after** that block in both files. `dxfToProject(text, { uid, L, colors, catalog, name, units, walls, rooms })` → `{ project, stats }` (one floor; `wallH` 270, `wallT` = median wall thickness or 20). Entry points: `openPlanFile(file)` (`#fileOpen`, drop on `#stage`) reads a `.dxf` as an `ArrayBuffer` → `dxfDecode(bytes)` → `importDxfText()` → `newTabSlot()` + `loadProject()`; a `.dwg` only gets a toast explaining how to save it as DXF (`dxfErr` words the `'DWG'` / `'binary DXF'` errors). MCP: `import_dxf { path, name?, units?, walls? }`.
- **Text & units.** `dxfDecode` tries strict UTF-8 (2007+ files), else the `$DWGCODEPAGE` code page (`DXF_CODEPAGE`, e.g. `ANSI_1254` → `windows-1254`, default `windows-1252`), strips a BOM, and throws on binary DXF or a DWG (`AC1…` header). `dxfStr` decodes `\U+XXXX` and `%%d / %%p / %%c`, `dxfMtext` strips MTEXT formatting and splits `\P` lines. Units: `opts.units` (`DXF_UNIT_KEYS`) → `$INSUNITS` (`DXF_UNITS`) → a guess from the 2–98 % coordinate span (mm / cm / m, or in / ft when `$MEASUREMENT` is 0; closest to a 25 m plan), `stats.unitsGuessed`. When guessed, the import toast has **Units…**, which re-imports into the **same** tab (`importDxfText(text, name, unit, true)`). Plan `x = X`, `y = −Y`, shifted near 0 in 1 m steps (percentile bounds, so a stray far-away object does not throw the shift).
- **Layers & style.** Used DXF layers become `P.layers` (name, colour, off / frozen → `vis: false`, locked, plot flag / `Defpoints` → `print: false`); layer `0` maps to Default; unused layers are dropped. Colour (ACI `DXF_ACI` / true colour 420, BYLAYER / BYBLOCK), line type (`dxfDash`: dashed / dotted / centre) and line weight (370, 1/100 mm → `w` cm, ≈ 1:100) go onto drafting objects; layer-0 entities inside a block inherit the insert's layer. `dxfInk` turns near-white into theme ink (`null`) and darkens light colours (yellow, cyan) so they read on white paper and in dark mode.
- **Entities.** `LINE`, `LWPOLYLINE` / 2D + 3D `POLYLINE` (bulge arcs via `dxfBulgePts`, wide polylines keep their width), `ARC` / `CIRCLE` (kept as draft arcs / circles under similar transforms, tessellated otherwise), `ELLIPSE`, `SPLINE` (NURBS `dxfSpline`, else fit points), `SOLID` / `TRACE` / `3DFACE`, `HATCH` (polyline + line / arc / ellipse / spline edges; solid or pattern fill, inner loops unfilled, no outline), `LEADER`, `MULTILEADER` → `drafts`; end-to-end `LINE`s of the same style chain into one polyline. `TEXT`, `MTEXT` (one text per line, attachment point honoured), visible `ATTRIB` → `texts`; linear `DIMENSION` (aligned / rotated) → `dims`, other dimensions are drawn from their `*D` blocks. OCS (`210/220/230`, mirrored arcs) via `dxfOcs`. `INSERT` / `ACAD_TABLE` expand recursively (`DXF_MAX_DEPTH` 12): rotation, scale, mirror, row × column arrays. Skipped and counted in `stats.skippedTypes`: paper space (`67 = 1`), invisible entities, `POINT`, `XLINE`, `RAY`, polyface / mesh polylines, images, ACIS solids, proxies; xref blocks are counted in `stats.xrefs`. Limit: `DXF_MAX_DRAFTS` (40 000 drafting objects, the rest in `stats.truncated`).
- **Blocks → furniture / openings.** A block whose name (camelCase and digits split) matches `ifcCatKey` becomes a catalogue item (bed / sofa / table variants by size, size sanity-checked so a "TABLE" title block is not a table): `w` / `d` from the block's local bounding box (`boxOf`, cached), rotation from the insert, long side turned to the catalogue's. A block or insert layer named like a door / window (`DXF_RX_DOOR`, `DXF_RX_WIN`) is an opening candidate; its linework stays as drafting only when it finds no wall.
- **Walls (unless `opts.walls === false`).** `MLINE` (centreline + element offsets along the miter, 4–120 cm), wide polylines (4–80 cm) and parallel line pairs (`dxfPairWalls`: 1° angle buckets sorted by offset, 4–80 cm apart, nearest pair first, each segment's used stretches tracked so one outer line pairs with several inner ones) on wall layers (`DXF_RX_WALL`: WALL, DUVAR, A-WALL, MUR, WAND, PARED, PERDE …) become walls; sources ≥ 80 % consumed, fills on the wall layer and short wall-layer lines inside a wall body (jambs, end caps) are dropped. `dxfMergeWalls` joins collinear walls of the same thickness and layer across gaps ≤ `DXF_WALL_GAP` (40 cm, T junctions) and turns gaps in `DXF_OPEN_GAP` (50–320 cm) into openings when there is evidence: a door / window block in the gap, a door arc hinged at a gap end (`dxfOpening`: hinge → `flip`, arc mid point → `side`; two arcs → double; the leaf line goes too), lines on a window layer, or ≥ 3 parallel lines spanning it. Door / window blocks lying on a continuous wall become openings sized by their extent along it. `ifcJoinWalls` then closes corners, and openings are re-projected so the moved wall ends do not shift them.
- **Rooms.** Closed polylines on room layers (`DXF_RX_ROOM`, ≥ 1 m²), else `ifcRooms(walls)`; the largest text with letters inside a room (texts on room layers first) becomes its name and is removed from the plan.
- **Layer → walls (`lyrwalls`).** When a drawing's wall layer has a name the importer does not know, the layers panel shows **🧱** on every layer holding drafting lines (`layerDraftCount`); `layerToWalls(lid)` runs `dxfPairWalls` + `dxfMergeWalls` + `ifcJoinWalls` on that layer's unlocked polylines, deletes the consumed drafts and commits once (undoable).
- Also fixed with this: `draftSvg` wrote an empty `stroke-dasharray`, so dashed / dotted / centre drafting lines rendered solid.
- **Not built:** binary DXF, DWG, xref loading, dynamic-block names of anonymous `*U` inserts, MTEXT word wrap, text styles / fonts, `MLINESTYLE` colours, layouts / paper space, hatch islands as holes, Z / 3D solids, splitting levels into floors (DXF export: see *DXF export*). Guard: `tests/dxf-import.test.js` (fixture `tests/fixtures/plan.dxf`, regenerated by `tests/fixtures/make-plan-dxf.js`) + the smoke check "DXF import: …".

- **R2000 (`AC1015`) structure.** `HEADER` (`$ACADVER`, `$DWGCODEPAGE ANSI_1252`, `$EXTMIN/MAX`, `$LIMMIN/MAX`, `$INSUNITS`, `$MEASUREMENT 1`, `$LUNITS 2`, `$HANDSEED`), empty `CLASSES`, `TABLES` (`VPORT`, `LTYPE` ByBlock / ByLayer / Continuous / DASHED / DOT / CENTER, `LAYER`, `STYLE`, `VIEW`, `UCS`, `APPID`, `DIMSTYLE` (handle code 105), `BLOCK_RECORD` for `*Model_Space`, `*Paper_Space` and every block), `BLOCKS`, `ENTITIES`, `OBJECTS` (root `DICTIONARY` + `ACAD_GROUP`). Hex handles from `0x20`, `330` owner pointers, subclass markers. Checked with `ezdxf` (`audit()`: 0 errors, 0 fixes) while building it; CI does not run ezdxf and nothing was opened in AutoCAD itself.
- **Units, coordinates, text.** `opts.units` → `DXF_EXP_UNITS` (`mm` / `cm` (default) / `m` → scale + `$INSUNITS` 4 / 5 / 6). CAD axes: `X = x`, `Y = −y`; rotations negated. `dxfExpStr` writes non-ASCII as `\U+XXXX` (what AutoCAD writes in R2000), so the file is pure ASCII with CRLF. Text height = font size × 0.72 (the importer divides by 0.72).
- **Layers (`DXF_EXP_LAYERS`).** `A-WALL`, `A-DOOR`, `A-GLAZ`, `A-RAIL`, `A-ROOM`, `A-ROOM-IDEN`, `A-SLAB`, `A-VOID`, `A-FURN`, `A-ANNO-DIMS`, `A-ANNO-TEXT`, `A-DRAFT`, `A-SKETCH`, `A-GRID`, `A-SECT`, `A-ANNO-TTLB`. Names carry the words the importer looks for (`DXF_RX_WALL` / `DOOR` / `WIN` / `ROOM`), and **only `A-WALL` matches `DXF_RX_WALL`** (test 3) — anything else on a "wall" layer would be paired into walls on re-import. `P.layers` are not written as DXF layers; `downloadDxf` drops hidden / non-printing ones through `visFloor(f, true)`.
- **Walls.** Each solid / curtain wall is split at its openings into pieces with two face `LINE`s on `A-WALL`. Corners: ends within 1 cm are grouped and sorted by angle (like `wallJoints`), and each face is extended / trimmed to its neighbour's face (miter, dropped above 2.5 × thickness), so corners need no filler. T junctions (an end inside another wall's body, `host` / `clip`): the faces stop at the through wall's face. Free ends get a cap on `A-WALL`; **jambs at openings go on the opening's layer** (`A-DOOR` / `A-GLAZ`) — two jambs of a ≤ 80 cm door on `A-WALL` read back as a wall across the door. Railings / fences: a closed `LWPOLYLINE` on `A-RAIL`; curtain walls add an `A-GLAZ` centre line.
- **Openings.** Local frame as in `opSvg` (x along the wall, mirrored by `flip`; y = wall normal × `side`). Doors / double doors: leaf `LINE` drawn open + swing `ARC` (`dxfExpArcAng`, start / end chosen so the CCW sweep is ≤ 180°); the importer reads `flip` from the hinge end and `side` from the arc. Sliding doors: two panel rectangles; arches: two dashed lines; windows: both faces + glass line on `A-GLAZ` (the importer's window evidence).
- **Furniture.** One block per `type | k | w | d | stepN | stairType | pts`, named `FP_<type>_<English name>_<w>x<d>` (ASCII, `_2` … on a clash; the English name is what `ifcCatKey` matches on import), drawn on layer `0` so it inherits `A-FURN`: rectangle, `CIRCLE` / 48-point ellipse for `round`, the outline for `poly`, plus treads (`geo.steps`) for stairs. `INSERT` at the item centre, rotation `−rot`. Tilted items (`geo.foot`) are a footprint `LWPOLYLINE`. Only footprints: the 2D catalogue symbols are not exported.
- **Rooms, slabs, voids, annotation.** Rooms: closed `LWPOLYLINE` + name and `m²` area `TEXT` (middle-centre) at the centroid; slabs: dashed outline; voids: outline + X. Drafts: `LINE` / `LWPOLYLINE` / `CIRCLE` / `ARC` with line type (`DXF_EXP_DASH`), weight (`dxfExpLw`, nearest standard 1/100 mm, = `w` × 10 as the importer reads it) and ACI + true colour (`62` + `420`); fills = `HATCH` `SOLID` or `ANSI31` (15 cm). Sketches: open `LWPOLYLINE`. Dims: `DIMENSION` type 1 (aligned, `70 = 33`) with an anonymous `*D<n>` block holding the lines, ticks and `fmtLen` text. Axes: `CENTER` line + bubbles; sections: line + name at both ends.
- **App side.** `downloadDxf(all = false, units = 'cm')` (`#bDxf` in the ⬇ menu, commands `dxf`, `dxfall`, `dxfm`, `dxfmm`) passes `geo = { arc: draftArc, foot, steps }`, `catName` (catalogue English name) and `fmtLen`; the file is `<project> - <floor>.dxf` when the project has several floors, and the toast's **All floors** button re-exports every floor (side by side along +X, 5 m apart, titles on `A-ANNO-TTLB`).
- **Not built:** 3D (`3DFACE`), an MCP export tool, curtain-wall mullions, room fills / floor patterns, 2D furniture symbols (footprints only), wall paint and per-face colours, terrain / site zones, roofs as roofs (footprint only). Round trip extras: a filled draft comes back as fill + outline, opening jambs and room area labels come back as drafting / text. Guard: `tests/dxf-export.test.js` + the smoke check "DXF export: …".

### One-click dimensions (#200)
- `autoDims(f)` (pure, before `detectRoom`) returns ordinary dims marked `auto: 1`: per room the minimum rectangle's (`ifcRect`) width and depth, a quarter of the way from the centre (inside, clear of the label); per side (`AUTO_SIDES` top / bottom / left / right, a `u` / `v` frame where smaller `v` = further out) the solid walls parallel to it (±2°) that are visible from outside (`vis`: at one of three sample points no other parallel wall lies in front), clipped where a wall in front covers them, give up to three chains `AUTO_DIM_GAP` (60) + n × `AUTO_DIM_STEP` (45) cm outside the outermost face: opening edges + wall pieces, wall pieces (when there are more than two points), overall. `autoDimsRun()` (project panel **📐 Auto-dimension** `data-act="autodims"`, command `autodims`) keeps manual dims, replaces the previous `auto` ones and commits once. Not built: sloped facades, dimension styles. Guard: `tests/auto-dims.test.js` + the smoke check "one-click dimensions …".

### Room detection (`detectRoom`)
Rasterises walls to an offscreen canvas (resolution ≥ 2 cm/px, max ≈ 1800 px), flood-fills from the click, returns `'open'` if the fill reaches the border (leak), otherwise traces the outer boundary and simplifies it (Douglas-Peucker, ε≈1.1·res). Doors/windows do **not** open rooms because the walls underneath are rasterised solid.

### Moving things (`startMove` / `doMove`)
- Snapshot originals in `ui.drag.orig`; apply a snapped **delta** from the first object's anchor (so off-grid objects keep their offset).
- Selected walls also drag coincident endpoints of non-selected walls (`conn`) so corners stay joined.
- Single furniture runs `magnet()`; openings re-project onto the nearest wall within 60 cm.
- Dragging a **single room** moves its contents too (`roomInner`: furniture + texts inside, captured in `startMove`); the panel's X/Y fields apply the same delta.

### Handles (`handleSvg` / `startHandle` / `doHandle`)
Handle ids: `wa/wb` (wall ends), `v<i>` (room vertex), `da/db/doff` (dimension), `rot` (furniture rotation), `c0..c3` (furniture resize), `bg0..bg3` (background image corner resize; preserves aspect ratio unless `Shift` is held). Shown only for a single selection. Background image (`id === 'bg'`) is selectable and movable on the canvas unless `P.bg.lock` is true. `g0..g3` (multi-selection bbox resize) appear when at least one *group-resizable* kind is selected (wall/dim/room/furn/text/sketch/bg — pure-op selections show none); scaling a wall re-projects its attached openings and shifts hinged-wall angle presets by the rotation delta.

### Storage
- `autosave()` (debounced) writes `P` to IndexedDB `state` store key `'auto'`; `beforeunload` also writes. Fallback to `localStorage['fp_auto']` if IndexedDB fails.
- Named projects live in the `projects` store (`{name, updatedAt, project}`, keyPath `name`). Saving with an existing name **overwrites**.
- `migrateLegacyStorage()` moves old `localStorage` keys (`fp_projects`, `fp_auto`) into IndexedDB once, then deletes them.
- Bumping `DB_VER` requires handling in `onupgradeneeded`; currently version 2 with stores `projects`, `state`, and `textures` (keyPath `'id'`, holds uploaded texture images outside `P` and undo history).
- **Background image (#187)** follows the same rule: `P.bg = { img, x, y, w, h, op, lock }`, the bytes (long side ≤ `BG_MAX` 4096 px after `downscaleImage`) in the `textures` store + `TEX` under `img`. `bgData(b)` is the only reader of the bytes, `bgAbsorb(b)` moves an inline `src` data URL out (upload, `normalizeProject` for old saves, share links, live-room assets), `bgInline(b)` puts it back for whatever leaves the browser as plain JSON (`bundleTextures` → ⬇ JSON, `shareLink`, `collabExportState`, `collabSendBgAsset`); Drive uploads it as one more texture file (`texRefIds`). `bgSvg` writes the `blob:` URL on the canvas and the data URL in exports. Guard: `tests/background-image.test.js` + the smoke check "large background image …".
- **Blocked storage (#188).** `localStorage` / `sessionStorage` are shadowed at the top of `app.js` by `safeStore()` wrappers (a global lexical binding hides the `window` property), so no read or write ever throws; without storage values live in memory for the session (`localStorage.ok === false`). A failed `openDB()` is not cached, and boot shows one bilingual warning when neither IndexedDB nor localStorage works. Guard: smoke check "boots and edits with browser storage blocked".

### Install as an app & offline (#203)
- `swBoot()` (end of the boot IIFE) registers `sw.js` only over http(s) (never on `file://`) and not with `?sw=off`. The worker precaches `SHELL` (app files, manifest, icons) and the pinned CDN scripts (`CDN` = the two `<script>` tags; a failed CDN fetch does not stop the install), caches Google Fonts on first use, and leaves every other request (bridge, Drive, workers) to the network. Deployed (`BUILD` stamped by deploy.yml): app files cache-first from `fp-<build>`; an older `fp-*` cache is deleted on activate. Not deployed (`__BUILD__`: local copy, the bridge's own page): network-first with the cache as the offline fallback, so edits show at once. A new worker waiting behind a controlled page → `toast(… { label: 'Reload', ms: 30000 })` → `postMessage('skip-waiting')` → `controllerchange` → reload (after `autosave()`). `reg.update()` hourly and when the tab becomes visible. **Add any new local file the app loads to `SHELL` and deploy.yml.** Guard: `tests/pwa.test.js` + the smoke check "install as an app and work offline".

### Project sync: Google Drive, share links, windows
- **Stable project identity (`P.id`).** `newProject()` assigns `pid()` (`uid() + uid()`); `normalizeProject()` in both `app.js` and `mcp/server.js` gives a missing / invalid id a new one, so sync and links know a project independently of `P.name`. Templates and new projects get a fresh id; opening a JSON file or a *My Projects* entry keeps its id unless that id is already open in a tab or synced with Drive on this device (`freshIdIfTaken`) — then it gets a new one, so an old copy can never be uploaded over the synced project. Everything lives in the section *Proje eşitleme* (after `projectsModal`); the UI is one header button `#bSync` (☁) → `syncModal()` (`ui.modal === 'sync'`), plus **☁ Sync & share…** in My Projects and the commands `sync` / `share`.
- **Share links & QR (`#fp=…`).** `shareLink()` = `APP_URL + '#fp=' + shareEncode(P)`: `1.<deflate-raw, base64url>` via `CompressionStream`, `0.<base64url>` without it. `APP_URL` is the page's own address, or `https://mewego.github.io/floorplanner/` on `file://` (a local path means nothing on a phone). The pure **QR-ENCODE** block (`qrEncode(text, 'L' | 'M')` → `{ size, mods, version }`, byte mode, versions 1–40; `qrSvg()`) draws the QR code when the link is ≤ `SHARE_QR_MAX` (1600 chars), else the dialog says to copy / share the link. Texture images are not in the link (surfaces fall back to plain colour). `openShareHash()` runs from `syncBoot()` and on `hashchange`, clears the hash with `history.replaceState` (a reload does not reopen it) and calls `openSharedPlan()`, which first closes the first-visit template picker. A tab already holding that `P.id` (`tabIndexOf`) is only switched to when its content is identical; if it differs (the link may be older), the link opens in a new tab as a copy with a new id and a " (link)" suffix — a link never overwrites an open project. Otherwise `newTabSlot()` + `loadProject()`. **📤 Send as a file** uses `navigator.share({ files })` where available, else downloads the JSON (`bundleTextures`, so textures travel).
- **Link plans are sanitised.** Every plan decoded from a link (`shareDecode`) goes through `sanitizePlan()` (a link can come from anyone): `" < > `` are removed from every string and key, `__proto__` / `constructor` / `prototype` keys are dropped, non-finite numbers become 0, `bg` is dropped unless `bg.src` is a base64 `data:image/…` URL, and `texData` keeps only `data:image/…` entries. Reason: builders interpolate values into double-quoted attributes without escaping (e.g. `bgSvg` writes `bg.src` raw), so a crafted link would otherwise run script on a single click. `app.js` has **no single-quoted attribute interpolation** — keep it that way, or extend `sanitizePlan`. Drive files are **not** sanitised: with `drive.file` the app only reads files it created for this user, so they are as trusted as a JSON file opened with 📂 (also not sanitised), and stripping would silently drop real characters (`12" pipe`) and spread that to every device.
- **Same-browser windows (`BroadcastChannel('fp-projects')`).** `bcInit()` (from `syncBoot`) listens with a per-window `WIN_ID`. `autosave()` now sets `saveTimer = null` when it fires and calls `syncNoteSave()` → `bcPost()` (the whole `P` as JSON) + `gdSyncSoon()` after a successful write. A receiving window adopts the project when its active tab has the same `P.id` (`adoptActive`, toast, undo returns), or replaces a background tab's `P` (+ history entry); it ignores the message while its own save is pending (`saveTimer` set — its version follows and wins, i.e. last edit wins; edits made in two windows at the same moment are not merged) or mid-action (`syncIdle()`: drag, wall / polygon / dimension / pen / drafting in progress, furniture studio, texture dialog). `bcPost` skips a plan identical to the last one sent or received (`bcLast`), so tab switches and adopted plans are not re-broadcast.
- **Google Drive (`gd*`).** No server: the browser talks to the Drive REST API with `fetch` and an OAuth token from Google Identity Services (`https://accounts.google.com/gsi/client`, loaded lazily by `gdLoadGis()` — when the dialog opens, or at boot if sync was on — because the sign-in popup must open inside the click). Scope `drive.file` only (files this app created). Client id: the `GDRIVE_CLIENT_ID` constant, or the dialog's *Advanced* field (`localStorage['fp_gdrive'].cid`, for forks); without one, or on `file://`, the Drive section explains instead of offering Connect. Token in `sessionStorage['fp_gd_tok']` (`{ t, exp }`, survives a reload of that tab); `localStorage['fp_gdrive']` = `{ on, user, cid }`; per-project state in `localStorage['fp_gdrive_state']` = `{ [P.id]: { f: file id, v: Drive version, h: strHash of the last synced JSON } }`.
  - Layout in Drive: folder **Floor Planner** (`gdFolder`), one `<name>.fp.json` per project (`appProperties { fp: '1', fpId }`, content = plain `P`, so it also opens with 📂), one file per custom texture (`appProperties.fpTex`, `gdPushTex` uploads missing ones, `gdPullTex` fetches unknown ones into `TEX` + IndexedDB). Uploads are single multipart requests (`gdUpload`).
  - `gdSyncOnce()` (only the **active** tab; others sync when activated, because activation autosaves): no state → find the file by `fpId` (base unknown) or create it; a pristine project is never uploaded. Then compare Drive `version` with `v` and the local hash with `h`: only local changed → PATCH; only remote changed → `adoptActive` (toast, undo works); same content → just record the version; Drive content equal to the last synced one (`st.h`, i.e. only the metadata changed: rename, star, move) → treat as a local-only change and upload; both changed → `gd.conflict` and the dialog asks (**Keep this device's** / **Use the Drive version** / **Keep both** = `gdResolve('mine' | 'theirs' | 'both')`; *both* gives the local copy a new `pid()` and a "(this device)" suffix and opens the Drive copy in a new tab). The dialog only pops up when no other modal is open; otherwise the ☁ dot turns amber. A trashed / deleted Drive file is recreated. If the tab or plan changes during a sync it reschedules (`gd.again`).
  - Triggers: 3 s after each autosave (`gdSyncSoon`), every 60 s while the page is visible, on `visibilitychange`, **⟳ Sync now**, and **💾 Save** (`saveBrowser` → `saveDriveStep`: connected → `gdSync(true)` at once; expired sign-in → a toast with a **Reconnect** button (`gdConnect`); never connected and `gdUsable()` → **☁ Also save to Google Drive** (`syncModal`) once per session, `ui.saveDriveHint`). **Save to Drive** (`gdEveryHtml()` in the connected section: `[data-gdmode]` after every change / on a timer, then `[data-gdeveryn]` number + `[data-gdeveryu]` s / m / h): `gdCfg().every` = seconds (`gdSetEvery` clamps to `GD_EVERY_MIN` 10 s – `GD_EVERY_MAX` 7 days), `everyU` = the unit shown, absent = after every change; `gdEvery()` is the only reader. ### Adjustable layouts & groups (vars)
- **Cross-floor groups (#86).** The record model is unchanged: every floor keeps its own `Floor.groups` record with the poses of **its** members. Records that share an `id` on different floors are **linked**: same number of layouts, same labels, same active `idx`. `grpLinked(gid)` lists them and `withFloor(i, fn)` runs the existing per-floor helpers (`find`, `F()`, `groupPoses`, `applyVarPoses`) as if that floor were active. `switchGroupVarTo` captures and applies every linked floor, then commits **once** (one undo step); `varAction` mirrors init / save / new / delete through `grpMirror()`, and `grpAlignVars()` pads missing layouts with that floor's current poses. UI: `grpLinkHtml()` (appended by `variantUIHtml`) offers **🔗 Link to a group on another floor** (`data-k="grplink"` → `linkGroupTo(gid)`: a local group takes the other id, or ungrouped objects become that group's members on this floor) and, when linked, the linked floor names + **🔗✕ Unlink floors** (`unlinkGroup` gives the local record a fresh id, keeping its layouts). Each floor draws its own badge for its members; 3D selects members on every floor (`groupMemberIdsAny`) and a click cycles all of them. Old projects have one record per id, so nothing changes; duplicating a floor gives the copy fresh group ids (not linked, not adjustable). Not built: dragging linked members on two floors together. Guard: `tests/features-84-86.test.js` + a smoke check.
- Groups: members carry `o.grp` (`GROUPABLE`: wall, room, furn, dim, text, slab — a free slab’s pose keeps `pts`, `off` and `t`; `applyVarPoses` restores `PTS_KINDS` by `pts`, never `x` / `y` / `rot`; a 3D click on a grouped slab selects the group / cycles its layout, `Alt` = the slab alone); per-floor `groups[]` holds `{ id, vars: [{ label, poses: {id: pose}, base?, draft? }], idx }`. Room variants live on the room itself (`r.vars`, `r.vIdx`). Clicking a room/group on canvas cycles layouts (`switchRoomVarTo` / `switchGroupVarTo`).
- `snapPose(kind, o)` snapshots an object pose (walls also keep `angles`/`posIdx`; rooms also keep `floor`, `color`, `glass` and `slabT` — #66, restored only when present so old pts-only poses keep the current finish); `applyVarPoses()` restores them — for legacy poses without angles it re-shifts existing presets by the body's rotation delta. `syncActiveVars()` refreshes the active variant's poses while the user edits.
- **First-come ownership:** `poseOwners()` maps id → owning layouts; `roomPoses` / `groupPoses` skip objects already claimed by another layout, so a wall shared by two rooms or furniture shared with a group layout is not double-moved. `dropPoseOrphans()` removes stale poses after ungroup / re-group / delete.
- A room polygon is clickable (`data-rpoly`) while it is selected, has its own layouts or belongs to a group with layouts (`grpHasVars`). In 3D, room floors (and their slab blocks / glass panels) carry `userData.roomId`; the click handler cycles the group or room layout (current floor only, `pickable`), `Alt` selects the room, and a room without layouts still behaves like empty floor (deselect).
- **Room slab thickness (#63):** `roomSlabT(r)` = `r.slabT` (0–200) or `ROOM_SLAB_T` (20) when absent, so old projects need no default. `build3D` extrudes a block of that depth 0.3 cm under the room finish (sides in the floor slab colour), which gives balconies and terraces drawn with the room tools a real edge; `0` keeps the old flat surface, glass rooms get none. Panel field `slabT` (hidden for glass), MCP `add_room` `slabThickness`.
- Alt+click selects a single group member **without** cycling its layout; the layout badge erased with the eraser deletes the whole group.
- **Editing members** (`ui.grpEdit = { id, fl, known }`, view-only): the group panel's **✏️ Edit members** (`grpEditHtml`) makes `grpEditing(o)` true for that group's members, so a click (2D and 3D) selects / drags a single member and never cycles the layout; `Esc` or **✓ Done** (`stopGrpEdit`) ends it. While it is on, `commit()` runs `grpEditAbsorb()` first: groupable objects that were not on the floor when editing began (`known`) join the group through `joinGroup(rec, objs)`, which also writes their current pose into **every** layout's `poses` / `base`, so each layout can then place them separately. Selecting a group plus ungrouped objects gives `varContainer()` type `join` → **➕ Add to group** (same `joinGroup`; `groupSel()` uses it too when it extends a single existing group). ### 3D interaction notes
- Picking uses `findAnyFloor()` (ids are unique across floors) and respects **occluders**: only the closest mesh hit is considered — walls/slabs/room floors hide furniture behind them.
- 3D group drags mirror 2D `doMove`: connected wall ends follow (`conn`), hinge pins translate (`pins`), room/sketch polygons update in the plan and are rebuilt into the scene on drop (`schedBuild3D`).
- `h3[]` holds one `BoxHelper` per selected furniture item, wall group or opening group, so grouped selections highlight too.
- **3D wheel zoom.** A `wheel` listener registered **before** `OrbitControls` (perspective only, not in walk mode; parallel projection keeps OrbitControls' zoom) replaces the dolly, which shrank its step with the distance to the target and stalled ("infinite zoom in"). The step comes from the distance to the surface under the cursor (one raycast per burst, cached 150 ms), at least 8 cm per notch, stopping 20 cm in front of a surface unless already closer (then it goes through), never below 10 cm above the ground. The camera moves along the cursor ray and `ctl.target` stays on the view line (no rotation) at ≥ 30 cm. 2D `MAX_ZOOM` is 40 px/cm (1 mm = 4 px) and `zoomAt` toasts once when a limit is hit. Guard: `tests/walk-climb.test.js` + a smoke check.
- **Walls & openings in 3D (issue #29).** Every opening is its own `THREE.Group` with `userData = { opId, elev }` inside the wall group (windows and arches included, not just door leaves). The 3D `pointerdown` handler starts `d3 = { op: true, … }` on an opening and stops propagation (no orbit); `pointermove` slides it with `opDragHit(ray, wall, elev)` — the ray hits the wall's vertical plane (floor plane fallback) and gives the distance along the wall — clamped like 2D and snapped to 5 cm, rebuilt via `schedBuild3D()`; `pointerup` commits after a drag, otherwise toggles a door (`Alt` = select only) or selects a window. The click handler selects plain walls (`Alt` also selects hinged / grouped walls instead of cycling) and always clears `downPt` first so a stale press cannot fire a second click. Height / thickness / type / paint and opening `w/h/sill` edits already rebuild through `affects3D`. Guard: `tests/edit-3d.test.js` + a smoke check.
- **Keyboard while in 3D.** The `if (ui.view3d)` branch of the window `keydown` handler owns the keyboard in 3D: `Escape` leaves, `WASD`/arrows/`Q`/`E`/`Shift` feed `keys3D`, and a **`ctrl` layer runs first** for `Z`/`Y` (undo/redo), `S`, `A`, `G`, `C`, `V`, `D` — plus `Delete`/`Backspace`. ### 3D (`build3D`, `furn3D`, `loop3D`)
- Plan `(x, y)` → Three `(x, elevation, z=y)`. Rotation: `mesh.rotation.y = -θ` (SVG clockwise → Three counter-clockwise). Room polygons use `rotation.x = +π/2`.
- Walls are split into boxes around each opening (below-sill, above-head). Solid walls also get **skirting** (both faces, skipping door gaps) and a thin **top cap** — `wt: 'curtain'` walls are skipped.
- Furniture detail is **parametric on the catalog id** in `furn3D(g, o, ctx)`: `sofa3/sofa2/armchair`, `chair`, `ochair`, `coffee|table*|desk|meet|vanity`, `deskPC`, `tableR`, `bed*|bunk|crib`, `wardrobe`, `dresser|night|shelf|bookcase` (`shelf|bookcase` are open carcasses with visible shelf boards, and bookcase adds book rows when detail is on), `fridge|dish|wm`, `stove`, `sinkK|counter*|island`, `basin*`, `wc|bidet`, `tub|shower`, `plant|tree`, `tv`, `rug`, `car`, `pool`, `column|colSq`, `fireplace`, `printer`, `stairs`. All proportions derive from `o.w/d/h` and shades from `o.color` (`shade()`), so 2D resize/rotate/swap never breaks it. **No new data fields.** Sub-part surfaces come from `sf(kind, colour)` (see *Model surfaces*, #93).
- `box/cyl/sph` share one unit `BoxGeometry` / `CylinderGeometry` / `SphereGeometry` and scale the mesh — do not allocate geometry per part. `EdgesGeometry` rides along with the unit box and is only added to silhouettes (the `edges` flag). Keep `furn3D` at ≤ ~40 meshes per item with detail on and ~12 with it off (~20 for stairs); the studio caps a converted model at 64 parts.
- Room floors use `r.floor` (`wood|tile|carpet|marble|concrete|stone|grass|water|gravel|deck|asphalt` or custom `tex:<id>`) to build cached `CanvasTexture`s tinted with `r.color` (`floorTexture()`, one texture per kind + colour + theme; `water` uses a translucent `MeshPhongMaterial` over a `waterBed`); `none` keeps the flat fill. The same textures finish the **floor slab** when `Floor.slabFloor` / `Floor.slabColor` are set (project panel → *Floor slab*); such slabs keep their material in the studio render (`userData.slab` is only set on default slabs). Painted walls (`w.color`) drive `wCol` in 3D, so skirting and top cap follow via `shade()`; in 2D `wallPaintSvg()` draws thin paint strips on both faces over the dark poché.
- Lighting: hemisphere + a shadow-casting directional light fitted to `contentBounds` (1024/2048 shadow map) + a low fill light. The renderer uses `PCFSoftShadowMap`, `outputEncoding = sRGBEncoding` and `ACESFilmicToneMapping` at ~1.05 exposure; ground, slabs and floors receive, large walls/furniture cast.
- Detail level: `build3D()` estimates the object count and drops part edges / frames / floor textures above ~3000 objects (`det` flag) instead of exposing a user setting.
- **Perspective / parallel camera (#74).** `T3.pcam` (perspective, `CAM_FOV`) and `T3.ocam` (orthographic, near −40000) share the orbit controls; `T3.cam` is the active one and **everything must read `T3.cam`, never a cached camera**. `setProjection(ortho)` copies position / orientation and keeps the image size (ortho half-height = distance · tan(fov/2), and back), and sets `T3.ctl.object`; `fitOrtho()` re-frames the ortho camera after every preset (`camAlong`, `set3DCam`, `orient3DFrom2D`, the default build camera). `setCamAspect(cam, a)` / `camAspectOf(cam)` replace `cam.aspect` (resize, captures, `render3DHQ`, whose jitter writes `elements[12/13]` for ortho instead of `[8/9]`). - **3D render export (issue #13).** `#b3dShot` (🎬, fourth button in `.ctl3dCam`) and the top-bar `#bPng` both produce a **rendered image**; `#bPng` is context-aware (`ui.view3d ? export3DRender(e.shiftKey) : exportPng()`) and `syncExportTitles()` keeps its tooltip honest (called from `show3D` + `applyLangUI`). Two paths, chosen by `Shift`:
  - **`export3DRender()` (default, `-3d-render.png`)** → `render3DHQ()`. This is a render, not a screenshot: (1) a studio preset (`opts.preset !== 'viewport'`) swaps `scene.background` to white, the ground to `0xf3f1ec` and every `userData.slab` mesh to the light slab colour, because in dark theme the near-black floor slab reads like a heavy drop shadow on white; (2) `LineSegments` (the per-box CAD outlines) are hidden for the passes — they are the single biggest "viewport" tell; (3) the shadow map is rebuilt **once** at 4096² with a frustum tightened to `T3.fit` and `r.shadowMap.autoUpdate = false` (re-rasterising it per pass cost seconds on a software rasteriser); (4) the scene is rendered into a `bufK` (2×) supersampled buffer over `frames` passes with Halton(2,3) sub-pixel jitter in `projectionMatrix.elements[8..9]`, each pass composited with `globalAlpha = 1/(i+1)` — a running mean on the GPU. `readPixels` + a JS sum loop did the same thing but was slower and allocated hundreds of MB; (5) the buffer is downscaled to `outW/outH` with `imageSmoothingQuality='high'` plus `sharpenCanvas()` (mild unsharp, 0.25 with supersampling / 0.6 without); (6) **everything is restored in `finally`** (background, ground/slab materials, edge visibility, shadow mapSize + frustum + autoUpdate, pixel ratio, aspect, `T3.run`, HUD).

Includes a title block (project, floor, date, total room area) and a 2 m scale bar. Background image is included only if its layer is visible.

### MCP server (`mcp/server.js`)
- **File paths are confined.** `load_project`, `save_project`, `import_ifc`, `import_dxf` and `add_texture` resolve their `path` through `fileArg(raw, exts, write)`: relative to the server's working directory, inside it or one of `FP_MCP_ROOTS` (platform path delimiter), checked before the file is looked up and again after symlinks are resolved, with the expected extension (`save_project` writes only `.json`, never through a symlink) and a 256 MB read cap. A prompt-injected agent cannot read or overwrite files elsewhere. Guard: `tests/mcp-paths.test.js`.
- **Optional tooling, not part of the app.** A zero-dependency Node (≥ 16) MCP server over stdio — JSON-RPC 2.0 is implemented by hand, so there is no `npm install` and no build. It lets AI agents (Claude Desktop, OpenCode, Cursor, …) author plans as JSON: `new_project`, `add_wall` / `add_rect_walls`, `add_opening`, `add_furniture`, `add_room`, `add_slab`, `add_void`, `add_text`, `update_object`, `delete_objects`, `add_floor`, `summarize`, `list_catalog`, `load_project` / `save_project` / `get_project` / `set_project`.
- **Live browser bridge (`mcp/bridge.js`).** IndexedDB is per-origin and a Node process cannot write it, so a tiny local server keeps the plan for the agent. **The client lives in `app.js`** (section *AI köprüsü istemcisi*), so the app connects to `http://127.0.0.1:8787` from **any origin** — the GitHub Pages build, a `file://` copy, or the bridge's own page. Nothing is injected and no script is loaded from the bridge. Pushed plans (`push_to_browser` → `PUT /__plan.json` → SSE `event: plan`) are applied through the app's own `loadProject()`, so autosave persists them to this origin's IndexedDB (refresh keeps them); local edits are pushed back on every `autosave()` (debounced, guarded by `brgApplying`). **Probing is opt-in (#192):** a fresh browser sends nothing to `127.0.0.1` at boot; `aiBridgeBoot()` probes only when this browser connected before (`localStorage['fp_bridge_used']`, written on the first SSE open, or the older `fp_bridge_rev`). Opening the AI dialog or 🔌 calls `brgWant()` + `brgProbe()`; after that `brgStartProbe()` keeps retrying with a `setTimeout` backoff (`BRIDGE_DELAYS` 10 s → 1 min → 5 min, `brgProbeDelay`), skips attempts while `document.hidden` and tries at once when the tab becomes visible, so a page that was already open still connects once the agent starts the bridge. Guard: `tests/ai-bridge-ui.test.js`.
- **`?bridge=off`.** Opening the app with this query (`BRIDGE_OFF`) disables the bridge client entirely — `brgFetch` throws, `brgConnect` returns false, `brgStartProbe` never polls. `tests/browser-smoke.js` always opens the app this way: it loads test plans, and a tab connected to a running bridge would push them over the user's live AI plan (it did, before this switch). Users can use it too, e.g. to look at a plan without syncing it.
- **Which plan wins on first contact.** `brgInitialSync()` compares the bridge revision with `localStorage[fp_bridge_rev]`: a returning browser adopts the agent's plan only when `rev > seen`; a **brand-new** browser (no `seen`) adopts it only if the local plan is pristine (no walls), otherwise its own plan wins and is pushed. After that, sync is revision-ordered, so a reload never re-pushes or oscillates.
- **Origins (security).** Browsers let any website send requests to `127.0.0.1`, so every bridge endpoint except the static app files answers **403** to a browser `Origin` that is not allow-listed (`originTrusted`): the deployed `https://mewego.github.io`, the bridge's own `http://127.0.0.1:PORT` / `http://localhost:PORT`, and `FP_ORIGINS` / `FP_WAKE_ORIGINS` extras. No `Origin` header = a local process (the MCP server, curl) = allowed. `Origin: null` (`file://` pages, but also sandboxed iframes on any website) is refused unless `FP_ALLOW_FILE=1`; a `file://` user opens `http://127.0.0.1:8787/` instead. Untrusted sites therefore can neither read the plan / snapshots / SSE, nor push, restore, queue or ack a request (no prompt injection into the agent's queue).
- **CORS / Local Network Access.** The bridge echoes a trusted `Origin` in `Access-Control-Allow-Origin` (`*` only when there is no Origin) plus `Access-Control-Allow-Private-Network: true` and `Vary: Origin` on every response (including preflights and SSE). Chrome 152+ (desktop) reaches `127.0.0.1` from `https://mewego.github.io` directly; newer builds may show a one-time **local network** permission prompt, and headless Chrome denies it outright (`LocalNetworkAccessPermissionDenied`) unless `--disable-features=LocalNetworkAccessChecks` is passed.
- **AI modal (`aiModal`).** The **🤖 AI** toolbar button (`ui.modal === 'ai'`) is a single-purpose panel: it reports live-connection state (`aiSyncLiveRow`), offers **📋 Copy agent prompt** (`aiSetupPrompt()` + `copyText()`, `navigator.clipboard` with a textarea/`execCommand` fallback because `file://` often blocks the async API) and **🔌 Try to connect** (`brgConnect()` + `brgInitialSync()`). There is deliberately **no copy/paste-the-JSON path** — the agent edits the plan directly, and a second weaker flow only confused users.
- **User → agent request queue.** The bridge client in `app.js` renders a floating, read-only **`AI` pill** (only when a bridge is connected; green dot + live revision) that opens a panel with bridge details and an **Ask AI** box. The agent prompt lives in `aiSetupPrompt()` and is offered in the **AI modal** (path 1) and **❓ Help**; it tells the agent to start `mcp/bridge.js` — no `http://127.0.0.1:8787/` visit, no file juggling. Submissions go to `POST /__requests`, are kept in bridge memory, and are read by the agent with `get_user_requests` / cleared with `ack_user_requests` (SSE `requests-changed` refreshes the open panel). Requests are **not** pushed to the model automatically unless the bridge was started with `FP_WAKE=1`; the UI must stay honest about that: the pill carries an amber **pending counter** (`data-ai-pending`, fed by `brgRefreshPending()`/`brgSetPending()` on SSE `request` + `requests-changed`) and the panel keeps "⏳ N request(s) waiting - tell your agent" visible until the queue drains, then shows "✓ Your agent picked it up" (`aiSyncSendState()`). Do not replace that with a short timer: a 5 s confirmation that disappears is indistinguishable from a request that vanished. UI is bilingual via `L()` and repaints on `data-theme` changes (MutationObserver); the pill has no pause switch by design.
- **Optional auto-wake (`FP_WAKE=1`).** When a request arrives the bridge can prompt the agent's own runtime instead of waiting for the human: it shells out to `opencode-cli api post /api/session/{id}/prompt --data {text, delivery:"queue"}` (the body tells the agent to call `get_user_requests` → edit → `push_to_browser` → `ack_user_requests`). `newestSession()` picks the newest session whose `location.directory` equals the repo; note `/api/session` returns `{ data: [...] }`, not `{data:{sessions}}`. `FP_WAKE_SESSION` pins a session (no re-resolve), `FP_WAKE_CMD` is a generic escape hatch (request text on **stdin**, detached, `parseCmd()` avoids `shell:true` quoting bugs on Windows), `FP_OPENCODE_CLI` overrides path discovery. Two gates: `FP_WAKE=1` **and** `originMayWake()` (browser origins must be in `FP_WAKE_ORIGINS` ∪ `mewego.github.io` ∪ the bridge's own origin; no `Origin` header = local process, allowed) — otherwise any website reaching 127.0.0.1 could drive the agent. `/health` and `GET /__requests` expose `wake`/`wakeAgent`/`wakeSession`; the client reads it into `brgWake` and swaps the pending text to "waking your agent…". Wakes are debounced 900 ms so a burst is batched.
- **Pill placement.** `placeAiPill()` positions the host above the footer using its measured height (re-run on `resize` and when built), and the panel gets a computed `max-height` so it never runs off short windows. The host uses `z-index: 95` — below `#modalbg` (100) — and opening Help closes the panel.
- **Saved versions / "go back" (snapshots).** AI edits replace the whole plan, so `mcp/bridge.js` writes JSON snapshots to `.fp-history/` (gitignored): `checkpoint(plan, 'before-ai'|'after-ai'|'before-restore', label)` runs only when the push's `tab` looks like an agent (`/^(mcp|agent|ai)/i`), because app autosaves are constant and the app already has `hist[]`. `checkpoint()` dedupes identical JSON (`lastHistJson`), keeps `FP_HISTORY_MAX` (default 60) files, and maintains `index.json` so history survives a bridge restart (`loadHistory()` at boot). `GET /__snapshots` lists metadata newest-first; `POST /__snapshots/restore {id}` validates the id against `/^h[a-z0-9]+-[a-z0-9]+$/i` (no traversal), checkpoints the outgoing plan, installs the old one and bumps `rev` with `tab: 'restore'` — so a restore is a normal revision, reaches the app through the existing SSE path, and is itself undoable. MCP side: `list_snapshots` / `restore_snapshot`, plus a `label` argument on `push_to_browser`. Client side: `aiRefreshSnapshots()` renders the last 8 rows with a ↩ button in the AI panel, `aiRestoreSnapshot()` confirms then posts (applying the response only if SSE has not already done so). `brgApply(plan, rev, kind)` takes `'restore'` to toast "↩ restored" instead of "AI plan applied". **Do not snapshot browser autosaves** — that would fill the history with noise and slow every push.
- The bridge client is now part of `app.js` (section *AI köprüsü istemcisi*), so it depends on normal module scope rather than injected globals: `loadProject`, `autosave` (wrapped), `toast`, `L`, `schedBuild3D`, `ui`, `closeModal`. `mcp/bridge.js` no longer injects anything and serves only the endpoints below.
- The workflow is file-based too: the agent saves a plan `.json`, the user opens it in the app via **📂 Aç**; exports from the app (**⬇ JSON**) can be loaded back with `load_project`.
- `CATALOG`, `OPENINGS`, `ROOMCOL`, `newProject`/`newFloor` defaults and the `mkWall`/`mkOp`/`mkFurn`/`mkRoom`/`addRectWalls`/`deleteIds` mirrors must stay **in sync with `app.js`** — when you change the data model or catalogue, update both files (and run `node --check mcp/server.js`).
- `opencode.jsonc` registers the server for OpenCode (`node mcp/server.js`). Never `require()`/import it from `app.js`: the app must remain dependency-free and `file://`-runnable.

## 9. Common Tasks (recipes)

### Add a furniture item
For a part-based item, also add a parts generator to `CAT_PARTS` in **both** `app.js` and `mcp/server.js` (put the generator inside the shared `PARTS-ENGINE` block). Append a row to `CAT_DEFS`: `['id', catIndex, 'Türkçe Ad', w, d, h3D, 'emoji', 'rect|round|bed|sofa|stairs', '#hexColor', 'English Name']`. Optionally reference it in a template via `c.fu('id', x, y, rot)`. For a new *shape kind*, extend `furnBody()` (2D) **and** the `build3D()` furniture branch.

### Add a door/window type
Add to `OPENINGS` (`id,name,en,w,h,sill,icon`), map its `id` to a `type` in `opType()`, draw it in `opSvg()` (use `pal()`), add a 3D representation in `build3D()` if needed, and add the option to the `type` `<select>` in `renderProps()`.

### Add a property to an object
1. Default it in the `mk*` factory **and** `loadProject()` (back-compat).
2. Add an input in `renderProps()` with `data-k`/`data-p` using `fld(L('TR', 'EN'), ...)`.
3. Use it in the SVG builder (and `build3D` if relevant).
4. `applyProp` already handles generic `o[p] = v`; add special cases only if needed.

### Add a tool
Add to `TOOLS` (`['id', 'icon', 'TR', 'Key', 'EN']`) + `HINTS` / `HINTS_EN`, handle it in the `pointerdown` `switch(tool)` (and `pointermove/up` if it drags), draw previews in `drawPreview()`, add a key in the `map` object in the `keydown` handler, document it in `helpModal()` and the README shortcut table.

### Add a grid type
Add `<option>` in `index.html#sGridType`; add patterns in `defsSvg()`, selection in `gridSvg()`, snapping in `snapToGrid()`, and (if angular) the angle step in `snapPt()` / label in `syncGridUI`.

### Add a template
Push an entry to `TEMPLATES` using `tplCtx()` helpers: `rect(x0,y0,x1,y1)` returns `[top,right,bottom,left]` walls, `W()` extra walls, `op(wall, d, openingId, extra)`, `fu()`, `room(x,y,name,color,floor)`. Door `side=1` on the outer rectangle swings **inward**. Check the thumbnail renders (templates modal).

### Bump schema
Increment `P.v` in `newProject()`, add a migration branch in `loadProject()`, keep reading older versions.

### Adding a test

Tests are **zero-dependency** (`node:test`, `node:assert`, global `fetch`/`WebSocket`). No `package.json`, no `npm install` — keep it that way so the app stays double-clickable. Put pure logic in `tests/helpers/` so it can be proven against synthetic input (see the `#b3dFit` regression test).

- **Run the real code, never a copy.** Cut functions out of `app.js` with `fnSrcOf(src, name)` (brace-aware; never `indexOf('
}')`) and run them in a `new Function` sandbox with small stubs. A hand-written "mirror" of an app function keeps passing after the app changes (the old camera tests did). If logic is buried inline in a big function, extract a small named helper first (e.g. `keepCam3D`).
- **Shared helpers** (`tests/helpers/repo.js`): `read`, `fnSrcOf(src, name)` (skips the parameter list and regex literals, keeps `async`; `syntax.test.js` proves it cuts every named function in `app.js` and `mcp/server.js`), `constLineOf(src, name)` (the line declaring `const name =`, whole-word match), `matchBracket(src, i)`, `markerBlock(src, 'PARTS-ENGINE' | 'IFC-IMPORT' | 'TEXGEN' | …)` for the blocks shared with `mcp/server.js`, `mcpClient()` (`call` / `tool` over stdio), `makeRng(seed)` (deterministic PRNG), `wallTopSrc`. Reuse them instead of copying slicers, const extractors or JSON-RPC clients into a test file, and give fixtures the fields real objects always have (furniture `rot`) rather than stubbing the function that reads them.
- **Source-text regexes** are a last resort for what neither a sandbox nor `browser-smoke.js` can reach (event-handler ordering, the synchronous capture contract). Don't add one that only re-checks an id (`dom-contract.test.js` covers every lookup) or a flow a smoke check already drives.

When you add a toolbar button or panel, add its id to `index.html` **and** to the `DOM contract` expectation list in `tests/dom-contract.test.js` if it is user-facing.

Headless screenshot (Windows, Edge) — useful for visual regression:

## 11. Pitfalls & Gotchas

- **Do not call `commit()` inside `render()` or per-mousemove** — it floods history.
- `render()` rewrites `innerHTML` of every layer; keep references to DOM nodes out of long-lived variables.
- `renderProps()` rebuilds the panel — don't call it while the user is typing in a panel input (use `render()` for live feedback; `renderProps()` only on `change`/selection change).
- Selection ids may refer to objects on **another floor** after switching floors — `find()` searches only the current floor; filter `sel` when changing floors/undoing (already done in `restore`).
- `ui.exporting` and `view.z` are temporarily mutated inside `exportSvg()`, `thumbSvg()`, `projectThumbSvg()`; they restore in `finally`. Preserve that pattern (these swap the global `P`/`fi` too).
- Wall length labels use `view.z` for font size; builders called outside the live canvas must set `view.z` first.
- **Never call `prompt()` / `confirm()` / `alert()`** (`tests/dialogs.test.js` fails): use `askText(title, def, { msg, validate, list, inputmode })` → text | `null`, `askNumber(...)`, or `askConfirm(msg, { title, ok, cancel, danger })` → `true` | `false` (the second button) | `null` (Esc / backdrop: change nothing). They return Promises, so the code after them runs later — re-find objects by reference when you continue (a re-render may have replaced arrays or DOM nodes) and `commit()` once inside the `then`. Smoke checks answer them by clicking `#ask [data-ask="ok"]` (see the `answer()` helper in the checks), not by stubbing `window.prompt`.
- `localStorage` writes can throw (quota/private mode) — keep them in `try/catch`.
- Room polygons are **not** linked to walls; don't assume they update when walls move.
- Emoji icons in furniture/library depend on the OS font; always keep a text name.
- Heavy rooms: `detectRoom` allocates up to ~3.2 M pixels; avoid calling it in loops or on mousemove.

### Editing-tool caveats (for AI agents)
- `app.js` and other files may have **CRLF** line endings depending on the platform/git config (git warns "LF will be replaced by CRLF"). Exact-match edit tools can fail on multi-line targets — prefer **small single-line targets**, or do a scripted replace (Node/PowerShell) and re-run `node --check`.
- When rewriting via PowerShell, write files as **UTF-8 without BOM** (`[IO.File]::WriteAllText(path, text, (New-Object Text.UTF8Encoding $false))`). Turkish characters (ı ğ ş ç ö ü İ) must survive — console output may display them wrongly even when the file is correct; verify via a screenshot instead of the terminal.
- Backticks/`$` inside JS template literals are easy to corrupt through shell quoting — write a small `.js` fix script instead of one-liners, then delete it.

## 12. Git & Deployment

- Default branch: `main`. Remote: `origin` → `git@github.com:MeWeGo/floorplanner.git`.
- **Published files:** `index.html app.js style.css privacy.html manifest.webmanifest icon.svg icon-192.png icon-512.png icon-maskable-512.png` + `sw.js` with `__BUILD__` replaced by the commit id (`tests/pwa.test.js` checks the list against `sw.js` and the manifest).
- **Deployment is gated by CI.** `.github/workflows/deploy.yml` runs the whole test suite (`ci.yml`) and only then publishes to <https://mewego.github.io/floorplanner/>. A failing test on `main` leaves the live site on the previous good build.
- **Pages source must be "GitHub Actions"**, not "Deploy from a branch". The old branch mode published every push immediately, which is how a boot crash reached production. `configure-pages` asks to switch it (`enablement: true`); if the token lacks admin rights, set it once in **Settings ▸ Pages ▸ Source**.
- Workflow map:
  | File | Trigger | What it does |
  | :-- | :-- | :-- |
  | `ci.yml` | push to any non-`main` branch, all PRs, `workflow_call` | static tests + browser smoke |
  | `deploy.yml` | push to `main`, manual dispatch | calls `ci.yml`, then publishes |
- Commit style: short imperative subject (`Add triangle grid`, `Fix door swing on flipped walls`), body for rationale if non-obvious.
- Typical flow:
  ```bash
  node --test tests/*.test.js
  node tests/browser-smoke.js
  git add index.html app.js style.css tests .github README.md AGENTS.md
  git commit -m "<message>"
  git push
  ```
- Prefer a PR for risky changes: CI runs on the branch, and branch protection (if enabled) blocks a red merge. A direct push to `main` still cannot deploy broken code, but it does consume a failed deploy run.
- Do **not** commit: temp test pages, screenshots, scratch scripts, `node_modules`.
- Keep `legacy-index.html` untouched.

## 13. GitHub Issues

Issues live at <https://github.com/MeWeGo/floorplanner/issues>. Every new issue must carry:

- exactly **one type label** — what kind of work it is;
- exactly **one priority label** — when it should be picked up.

Bugs also get a `severity:` label (impact). Severity is separate from priority: severity says how bad it is, priority says when to schedule it.

| Group | Label | Use for |
| :-- | :-- | :-- |
| Type | `bug` | Broken behaviour, regressions, crashes |
| Type | `enhancement` | New features and user-visible improvements |
| Type | `documentation` | README / AGENTS.md / help text only |
| Type | `question` | Clarification, design discussion, support |
| Priority | `priority: high` | Blocks a release or a core workflow; pick up next |
| Priority | `priority: medium` | Important, but a workaround exists; schedule after high |
| Priority | `priority: low` | Nice-to-have, polish, long-term ideas |
| Severity (bugs) | `severity: high` / `medium` / `low` | Impact if the bug is hit |

- `duplicate`, `invalid` and `wontfix` are closing states, not types. `accessibility`, `help wanted` and `good first issue` are optional extras.
- A high-severity bug is not automatically high priority (e.g. a rare crash on an unused path), and a low-severity bug can be high priority (e.g. a typo in the main toolbar).
- Do not invent labels — check `gh label list` first.
- Body: summary, current behaviour, repro steps (bugs) or scope / non-goals (features), acceptance criteria, test notes. **Follow [`.github/ISSUE_GUIDE.md`](.github/ISSUE_GUIDE.md)** for the title format, section templates, what to leave out (line numbers, mockups, exact UI text) and the pre-filing checklist.

```bash
gh issue create --title "..." \
  --label bug --label "severity: medium" --label "priority: high" \
  --body-file issue.md
```
